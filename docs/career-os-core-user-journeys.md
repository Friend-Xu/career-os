# Career-OS Core User Journeys（用户工作流定义）

> 2026-08-04 | 目的：验证"用户每天打开 Career-OS 能不能把事情变简单"——UI 从旅程推导，不从页面推导
> 方法：JTBD（用户雇佣产品完成什么）+ Scenario-Based Design（具体场景）+ Task Analysis（任务拆解）
> 支撑状态：✅ 已有可用 / ⚠️ 有数据缺入口 / ❌ 缺失

## 使用模式（两种，不是一种）

| 模式 | 用户问题 | 内容 |
|---|---|---|
| **Daily Dashboard** | "我的职业状态怎么样？" | 当前方向/机会池/风险/建议行动 |
| **Task Workspace** | "我现在要完成什么事？" | 单任务的完整工作区（岗位投递空间/方向探索空间/面试空间） |

用户打开软件时带着具体任务（"我要投这个岗位"）→ 进入 Task Workspace；没有任务时 → Dashboard 给状态和下一步建议。

## Journey 1：投递一个岗位（最高优先级）

**JTBD**：用户看到岗位 → "我要不要投？这家公司能不能去？值得我投入时间改简历吗？"
**触发场景**：在招聘平台/官网看到 JD；或猎头推来一个岗位。

**投递决策 = 岗位匹配（能不能胜任）+ 公司评估（能不能去）两个维度，缺一不可。**

```
发现 JD → 保存岗位 → 理解要求 → 判断匹配 → 公司尽调 → 决定投 → 优化简历 → 投递 → 跟踪
```

| 步骤 | 用户操作 | 系统响应 | 状态 |
|---|---|---|---|
| 1.1 捕获机会 | 粘贴 JD（或输入岗位） | 创建 Job（JD 原文/技能要求）；确认公司档案存在 | ✅ |
| 1.2 理解要求 | 点"分析岗位要求" | Agent 拆解：必须 ✓ / 加分 ○ / 隐含要求 → 存 JobRequirement | ⚠️ 无此按钮（断点 1） |
| 1.3 判断匹配 | （分析后自动出现） | 技能覆盖：优势 ✓ / 缺口 △ / 建议 | ✅ gap 已有（仅卡片展开，入口弱） |
| 1.4 公司尽调 | 点"公司尽调"（新公司自动提示） | Agent：规模/市占率/风险/业务占比/入职建议 → 公司档案 | ✅ 尽调入口已有，但岗位流程内无提示（断点 2） |
| 1.5 决定投 | 综合岗位匹配 + 公司评估 | 两个维度并列展示（岗位匹配清单 + 公司档案摘要） | ⚠️ 未聚合（断点 3） |
| 1.6 优化简历 | 点"针对该岗位优化简历" | 生成简历修改建议 + ResumeVersion | ⚠️ 无岗位直达（断点 4） |
| 1.7 投递 | 点"已投递" | 创建 Application，状态 Submitted，记跟进日 | ✅ |
| 1.8 跟踪 | 系统自动提醒 | 超期未回 → "建议跟进" + 话术生成 | ✅（提醒在投递页，弱） |

**断点**：1.2 无按钮；1.4 岗位流程内无尽调提示（公司没查过，用户可能直接投被坑）；1.5 两维度未聚合；1.6 无岗位直达。
**价值验证点**：完成 1.2→1.6 后，用户感知应从"管理求职数据"变为"被辅助完成求职"——且**投递前先确认公司靠谱**。

## Journey 2：探索新方向（转行 / 新人入行）

**JTBD**：用户对现状不满或想入行 → "我该往哪走？"
**触发场景**：在职转行（"我想转 AI"）；新人入行（"我是应届生，该入哪行"）；已投方向受阻（"机器人方向没戏，看看别的"）。

```
方向分析 → 城市评估 → 公司池 → 岗位池
```

| 步骤 | 用户操作 | 系统响应 | 状态 |
|---|---|---|---|
| 2.1 方向分析 | 说"我想转 AI"（AI 面板）或点引导 | Agent：方向排序/匹配度/差距/行动计划 → 方向决策 | ✅ Agent |
| 2.2 方向产出 | 看方向视图 | 该方向全部决策时间线 | ✅ |
| 2.3 城市评估 | 侧栏 Location 空态 → "去分析" | Agent 城市对比 → 城市决策（深圳 86 分） | ⚠️ 空态引导未做 |
| 2.4 建公司池 | 公司探索 → 尽调 | 公司档案 | ✅ |
| 2.5 岗位池 | 浏览该方向岗位 | **岗位列表（按方向/公司聚合）** | ❌ 无岗位池浏览页（断点 3） |

**特别场景（多方向）**：用户已有方向 A 的基线，评估方向 B → 系统提示"方向 B 未建立基线，建议先做方向分析（可跳过）"→ 方向 B 的决策产生后，方向视图出现 B。⚠️ 提示未做。
**新人特殊点**：画像无技能声明 → gap 显示"未声明"，方向分析侧重行业认知而非技能迁移。✅（Agent 上下文自适应）

**断点**：2.3 空态引导未做；2.5 岗位池浏览页缺失（jobs 数据有了，没有独立浏览入口）。

## Journey 3：面试准备

**JTBD**：收到面试 → "我该准备什么？别浪费这个机会"
**触发场景**：投递状态变为"面试中"；或猎头约面试。

```
状态更新 → 公司分析 → JD 回顾 → 项目准备 → 问题预测
```

| 步骤 | 用户操作 | 系统响应 | 状态 |
|---|---|---|---|
| 3.1 状态更新 | 投递卡片 → 面试中 | 看板移动 | ✅ |
| 3.2 公司分析 | 点"面试准备" → 公司分析 | Agent：公司背景/业务/竞对 | ✅ 尽调入口可复用 |
| 3.3 JD 回顾 | 面试空间显示该岗位 JD | 岗位要求/匹配清单（已有数据） | ⚠️ 无面试空间聚合（断点 4） |
| 3.4 项目准备 | 点"准备项目介绍" | Agent：按岗位要求组织项目陈述 | ❌ 无入口 |
| 3.5 问题预测 | 点"预测面试问题" | Agent：按 JD+简历生成预测问题 | ❌ 无入口 |

**断点**：3.3-3.5 无聚合入口（面试空间缺失）——数据（JD/匹配/简历）都在，但没有"面试准备"的 workspace。

## 断点汇总 → 实施优先级

| # | 断点 | 影响旅程 | 严重性 |
|---|---|---|---|
| 1 | 岗位创建后无"分析 JD"入口 | J1 1.2 | 高（主旅程断裂） |
| 2 | 岗位流程内无尽调提示（新公司可能没查过） | J1 1.4 | 高（被坑风险） |
| 3 | 岗位匹配 + 公司评估未聚合（"投不投"无综合视图） | J1 1.5 | 中 |
| 4 | 无"针对该岗位优化简历"直达 | J1 1.6 | 高 |
| 5 | 岗位池无浏览页（jobs 独立入口） | J2 2.5 | 中 |
| 6 | 面试空间缺失（JD/匹配/简历聚合） | J3 | 中 |
| 7 | 初始化/多方向空态引导未做 | J2 | 中 |
| 8 | 匹配入口弱（藏展开层） | J1 1.3 | 中 |

**实施顺序**（断点 1/2/3/4/8 属于同一件事：**岗位 Task Workspace**——1.1 保存后进入，公司尽调/岗位分析/匹配/简历/投递都在这个空间里完成）：
1. **岗位 Task Workspace**（断点 1+2+3+4+8）：保存岗位 → [分析 JD] → 匹配 → [公司尽调]（公司未查过自动提示）→ 投决视图（岗位匹配 + 公司评估并列）→ [优化简历] → [已投递]
2. **岗位池浏览页**（断点 5）：jobs 列表（按公司/方向聚合），每岗位进 Task Workspace
3. **面试空间**（断点 6）：面试中岗位的 JD+匹配+简历+动作聚合
4. **空态引导**（断点 7）：初始化条 + 多方向提示

## 验证标准（怎么算"减轻负担"）

跑通 Journey 1 后，用户回答三个问题：
1. "我录入一个岗位后，**知道下一步做什么**"（系统推着走，不用找入口）
2. "判断值不值得投的时间**从 10 分钟降到 1 分钟**"（Agent 拆需求 + 匹配清单 + 公司尽调两维度并列）
3. "投完不会忘，**投前不踩坑**"（JD 保存 + 跟进提醒 + 公司尽调确认）
