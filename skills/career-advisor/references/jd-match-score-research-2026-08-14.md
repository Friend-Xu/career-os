# JD 匹配度调研记录（2026-08-14）

> 本文档是完整调研记录：行业做法细节 + 同类项目分析 + 开源技术路线 + 采纳决策）。
> 数据来源均为公开资料（网页/开源仓库），不含真实用户数据。

## 1. 调研目的

JD 匹配度引擎化（契约 v0.1）冻结后发现三类问题需要外部锚定：
① 权重口径的行业依据 ② 同义匹配误判（审计发现 19 项缺口中约 7 项为假缺口）
③ 同类项目怎么处理「匹配」这件事。本次调研覆盖：行业头部 HR 产品做法、
招聘行业开源规则、学术/工业匹配算法、同类 Claude Code 求职项目。

## 2. 行业权威做法（细节展开）

### 2.1 北森 EHR（行业头部 HR SaaS）——权重区间

| 维度 | 权重建议 | 适用场景 |
|------|---------|---------|
| 必备技能 | 30%–45% | 强专业岗位 |
| 行业/场景经验 | 15%–30% | 需要快速上手 |
| 产出指标 | 15%–25% | 结果导向岗位 |
| 通用能力 | 10%–20% | 协作密集岗位 |
| 教育/证书 | 5%–15% | 合规或门槛明确 |

关键实践：JD 拆解为岗位胜任力模型（必备项/加分项/风险项）；简历拆解为能力证据；
**每个分数可点开看证据**（命中原句、缺口项、待面试确认项）；权重用录用后表现回归校准
（闭环校准——AI 初筛 → HR 人工复核 → 持续校准）。

### 2.2 job-copilot（开源招聘工作流）——资格先行

- 校招：硬技能 30 / 项目实习 25 / 学历届别专业 20 / 证书语言 10 / 城市行业意向 15
- 社招：职级硬性要求 30 / 相关工作成果 30 / 技能 20 / 行业业务域 10 / 城市到岗意向 10
- **证据系数**：直接证据 = 1，可迁移证据 = 0.5，无证据 = 0
- **必需项权重 2、优先项权重 1**（我们标记为 Known Gap 待评审的 must/plus 2:1 出处）
- 硬门槛（届别/年限/执业资格）一票否决，eligible=false 不进入评分
- coverage = 有证据的评分项权重 / 全部评分项权重 × 100（我们 maxScore 收缩设计的出处）
- 档位：85–100 高度匹配 / 70–84 推荐投递 / 50–69 备选 / 0–49 观望

### 2.3 ATS 现实（2026 求职者视角总结）

关键词匹配约 60% + 格式可读性约 20% + 硬性门槛一票否决；大厂已从关键词升级为
**大模型语义匹配**（JD/简历向量化 → 余弦相似度 → 前 20–30% 进 HR 列表）；
智联招聘用**双塔模型** + Milvus 向量库做召回→粗排→精排→重排。

## 3. 同类优质项目：ai-job-search 1.5.0

本地参考：`docs/ai-job-search-1.5.0`（MadsLorentzen/ai-job-search，GitHub 趋势榜项目）。
同样是 Claude Code 求职工作流，作者真实战绩 69 投递 / 20 面试 / 1 offer。
核心资产：`.claude/skills/job-application-assistant/04-job-evaluation.md`（framework v1.2.2）。

### 3.1 评估框架（打分模型）

| 维度 | 权重 | 说明 |
|------|:---:|------|
| Technical Skills Match | 30% | rubric 分档（80-100 核心要求是主技能 / 60-79 大部分匹配有 1-2 个可学缺口 / 40-59 需显著补强 / 0-39 根本性错配） |
| Experience Match | 25% | 直接 / 可迁移 / 相邻 / 无关 四档 |
| Behavioral/Culture Fit | 15% | 文化匹配 + 红旗（维护性工作占比、领导化学反应等） |
| Location | 否决制 | 通勤内 PASS / 远程 PASS / 需搬迁 FAIL（deal-breaker 出局）/ 频繁出差 FLAG |
| Career Alignment | **30%** | 最大权重——含 energize/drain 任务清单、生活约束（经济安全/时间弹性/成长优先） |

判定档位：Strong 75+ / Good 60-74 / Moderate 45-59 / Weak 30-44 / Poor <30。

### 3.2 结构设计（可借鉴的四个机制）

1. **打分前两道硬闸**：Eligibility Gate（签证/公民身份——「沉默不是许可」原则：
   招聘帖没写 ≠ 接受）+ Language Gate（要求语言不在声明表 → FAIL 不打分；
   声明了但帖子要求可能更高 → FLAG 继续打分但明示差距）。FAIL 都引原文回给用户。
2. **两阶段评估**：`/rank` 分诊（只看帖子文本 + 画像，廉价批量）→ `/apply` 全量重评
   （带公司调研，权威）。分诊分永远不替代全量分——对应我们的「匹配度投影 vs 决策深分析」分工。
3. **诚实分持久化**：strengths/gaps 数组随分数落盘，禁止平滑——低分岗位如实呈现，
   「用户不同意排名 → 修画像或框架，不弯分数」。
4. **`/upskill` 缺口热力图**：硬技能 diff（**"be generous" 匹配**——画像提到 Python 即覆盖
   Python scripting）+ LLM 综合（领域知识/软技能/工具流程/证书缺口）→ 按
   `(100 - fit_rating)/100` 按岗位重要度加权 → 学习计划。**记录过的缺口优先于推断的
   技能**（provenance 原则——不猜）。

### 3.3 与我们的对照

| 维度 | ai-job-search | 我们（Career OS） |
|------|--------------|------------------|
| 打分执行 | AI 手评（rubric 分档约束） | **引擎规则合成**（确定性，可审计） |
| 输入事实 | 画像 + 帖子文本 | JD capabilities（结构化）+ 画像技能 + 门槛四态 |
| 缺口处理 | 落盘 + 加权热力图 | 规则行 + tooltip 展开 + Opportunity Loop |
| 硬闸 | 签证 / 语言 | 学历 / 专业 / 经验（NOT_MATCHED 否决） |
| 城市 | 否决制（不占权重） | **尚未做**（preference_constraints 有数据）——采纳点 ② |
| 职业方向 | 30% 权重主维度 | Known Future（触发条件 = 岗位方向结构化） |

两者都反对黑盒匹配分；执行层一个靠 rubric 约束 AI、一个靠规则表约束引擎——个人工具
可审计要求下引擎化更严格，方向正确。

## 4. 开源项目三派技术路线

| 派别 | 代表项目 | 同义处理 | 评价 |
|------|---------|---------|------|
| 语义向量 | JobVector（Gemini 768 维 + Supabase）、resume-saas（MiniLM）、LLM-Resume-Analyzer | Embedding 余弦相似度 | 召回好；黑盒、不可解释、需模型依赖 |
| 混合 | hybrid-lexical-semantic-matching | TF-IDF + MiniLM 加权 + 句子级解释 | 折中；复杂度高 |
| **词表 + 模糊** | ai-resume-screener（200+ 技能词表 7 域）、Resume_Scanner（fuzzywuzzy：JS↔JavaScript）、CareerCraft（规格：**禁止 LLM、确定性规则反馈**） | 受控词表归一 + 模糊匹配 | **确定性、可解释、零模型依赖**——本系统所属派别 |

共性结论：几乎全部项目都用**加权多因子评分**（技能 25–70% 为主导 + 语义 0–35% +
经验 15–25% + 教育 5–20%）；三分法分类（matched/partially/missing）与我们的
满足/可迁移/缺失同构——我们不是孤例。

## 6. 不采纳项与理由

- **黑盒向量匹配**（双塔/Embedding 相似度）：需要行为数据训练、不可解释、模型依赖——
  与个人工具定位（localhost、可审计、事实锚定）冲突。同义问题经 alias 数据层解决
  （结构化语义，不用向量语义）。
- **AI 手评总分**（ai-job-search 式 rubric 打分）：我们已走过这条路（directionMatch 52%
  的教训——rubric 存在但执行不落盘不可审计）。引擎规则合成是更严格的执行层。
