# 跨子流程一致性检查

> 汇总层在输出综合结论前必须执行。各子流程在写 decisions/ 时可选执行。

## 检查清单

### 1. 方向一致性
decisions/ 文件中 direction 字段是否指向同一方向？
不一致 → 标注矛盾，置信度降为"低"

### 2. 城市一致性
city 字段是否一致？不一致时 city_score 差异是否 >2 分？
差异 >2 → 标注矛盾

### 3. 置信度升级检测
上游标"低"的结论，下游是否升级为"中"或"高"？
升级了 → 强制还原，标注"上游数据置信度为低，不可升级"

### 4. 薪资可行性
career-transition 的 salary_feasible=false 但 city-advisor 推荐了高成本城市？
矛盾 → 标注

### 5. 风险遗漏
上游标了 key_risk，下游的分析是否覆盖了这个风险？
未覆盖 → 标注"上游风险未在下游体现"

### 6. 硬约束冲突
子流程的推荐是否违反 profiles/ 中的硬约束？
冲突 → 标注，置信度降为"低"

## 降级规则

| 检测到 | 动作 |
|--------|------|
| 上游数据 >30 天 | 标注"数据可能过期"，置信度降一级 |
| 与已有决策矛盾 | 标注矛盾，要求用户裁决 |
| 上游低置信度被升级 | 强制还原为低置信度 |
| 与用户硬约束冲突 | 标注冲突，置信度降为"低" |
| protocol_version 不匹配 | 标注"旧版协议生成"，置信度降一级 |

## 汇总置信度计算

```
基准 = 已完成子流程数 / 6 × 最低单子流程置信度

降级：矛盾→低 | 数据>30天→降一级 | ≤2 个子流程→低
升级：5-6 个子流程 + 无矛盾 + 数据 ≤7 天 → 可升为"高"
```
