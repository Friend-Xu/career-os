# 路径设计指南

跳板模式库 + 路径选择 + 时间线里程碑。

---

## 跳板模式库

每个模式有明确的前置条件（工作年限 + 职级要求）。
不满足前置条件的模式不应推荐。

---

### 模式 1: 技术线深耕（同领域不同层级）

```
路径: [一线工程师] → [系统工程师] → [技术专家]

前置条件: 无最低年限，随自然晋升过渡
跳板不需要刻意找，关键是从"执行者"到"设计者"的思维转变

发展路径:
  第 1-3 年: 从"画某个零件"升级到"理解整个系统怎么工作"
            多问"这个零件为什么要这样设计"
  第 3-5 年: 主动申请做跨模块的方案设计
            开始参与技术评审，学会评价别人的设计
  第 5-8 年: 成为某个子系统的技术负责人
            从"自己做"过渡到"把关团队的技术方向"

成本: 几乎为零
风险: 低（这是自然晋升路径）
不适合: 对当前领域完全失去兴趣的人
目标方向: 机械工程.md #19 技术经理/技术主管, #20 技术总监/CTO
```

### 模式 2: 机械 → 机电一体化 → 嵌入式/机器人

```
路径: [机械设计] → [机电一体化工程师] → [机器人/嵌入式工程师]

前置条件: 1-5 年机械背景 + 有编程兴趣（真的写过程序，不只是"想学"）

第 1 步: 在当前工作中找机电交叉点（6 个月）
  → 机械设计时主动了解电气选型、传感器布局
  → 申请做机电一体化的模块（如执行机构+电机+驱动）

第 2 步: 业余学嵌入式基础（6 个月）
  → Arduino → STM32
  → 做一个完整的机电项目（如"用 STM32 控制一个步进电机按预定轨迹运动"）

第 3 步: 找机电一体化工程师岗位（1-2 年）
  → 目标岗位：机电一体工程师（机械+简单电控混合岗）
  → 这个岗位是天然跳板——你懂机械是优势，电控部分在工作中学习

第 4 步: 在机电岗积累 1-2 年后深入学习 ROS/C++ → 机器人岗

总耗时: 2-3 年
成本: 低（在职学习为主，不需要脱产）
不适合:
  - 工作 5 年+ 的纯机械（学习曲线的机会成本太高）
  - 不喜欢写代码（这个路径最终需要编程能力）
目标方向: 机械工程.md #8 机器人本体设计, #15 嵌入式/电控工程师
```

### 模式 3: 研发 → 售前/解决方案 → 技术商务

```
路径: [研发工程师] → [售前/FAE] → [技术型销售/产品经理]

前置条件: 3 年+ 研发经验，对本公司产品深度熟悉

第 1 步: 主动参与客户交流（在当前工作中启动）
  → "下次客户来评审，我可以去讲技术方案吗？"
  → 观察售前同事怎么跟客户沟通

第 2 步: 内部转到售前/FAE（同一家公司内部转，风险最低）
  → 目标岗位：应用工程师/售前技术支持
  → 你的价值：客户问技术问题能直接答，不需要拉上研发

第 3 步: 在售前排做 1-2 年
  → 积累客户关系 + 行业人脉 + 理解甲方决策逻辑
  → 这时候你有：技术深度（研发底子）+ 客户认知（知道甲方怎么决策）

第 4 步: 分岔路口
  → 路线 A: 继续售前/销售 → 收入靠提成，天花板高
  → 路线 B: 转产品经理 → 从需求端出发做产品定义

总耗时: 1-3 年（取决于内部转岗的速度）
成本: 低（内部转岗为主）
不适合:
  - 不喜欢出差（售前/FAE 出差频率可能 30-50%）
  - 不喜欢应酬和商务场合
  - 不擅长在压力和模糊中做决策
目标方向: 机械工程.md #14 技术支持/应用工程师, #18 技术销售(工业品)
```

### 模式 4: 大厂 → 小厂/创业公司

```
路径: [大厂/中厂工程师] → [小厂核心员工] → [创业/自由职业]

前置条件: 3 年+ 在大厂/中厂 + 技术基础扎实 + 6 个月+ 生活费的财务缓冲

关键: 不要裸辞创业/跳小厂

第 1 步: 副业验证（6-12 个月）
  → 周末接小项目/帮人做方案/在行业社群建立个人品牌
  → 等到副业收入达到正职的 30%+，再考虑全职跳

第 2 步: 跳到小厂做核心岗
  → 目标：创业公司/中小企业的技术骨干
  → 大厂背书在你的谈判筹码——要股份、要title、要自主权
  → 风险：小厂可能倒闭、承诺的股权可能一文不值

第 3 步（可选）: 独立顾问/创业
  → 在小厂积累了"从 0 到 1"的经验 + 行业口碑后
  → 具备独立接项目或创业的条件

总耗时: 2-4 年
风险: 高
适合:
  - 年轻（<30 岁）、没房贷、对某个方向有强烈信念
  - 能接受"干一年公司倒闭"的不确定性
不适合:
  - 有家庭负担
  - 在"先别转"诊断中主要靠 Push 驱动（逃避比向往更多）
  - 财务缓冲 <6 个月
目标方向: 机械工程.md #22 独立顾问/自由职业 (8年+)
```

### 模式 5: 技术 → 技术管理

```
路径: [高级工程师] → [技术经理] → [技术总监]

前置条件: 5 年+ 一线技术经验 + 至少高级工程师 + 有带新人的经历（哪怕非正式）

核心认知: 管理不是"升职"，是"换职业"
  → 最大的心态转变：从"我做得最好"到"让团队做得最好"
  → 很多人转管理后不开心：怀念技术、管人很累、会议太多

建议先小范围测试:
  → 在当前公司带 1-2 个新人/实习生
  → 看自己是否享受"帮别人成长"这个过程
  → 如果带人让你烦 → 不适合走管理线，考虑技术专家路线

发展路径:
  第 1 步: 在当前公司争取带新人/小组长（非正式管理）
  第 2 步: 正式升技术经理 or 跳槽去需要建团队的中小公司
  第 3 步: 积累 3-5 年管理经验后 → 技术总监/CTO 路径

总耗时: 3-5 年（从高级工程师到技术经理）
风险: 中（最大的风险是你发现自己不喜欢管人，但已经转过去了）
不适合:
  - 真正热爱技术本身、不喜欢开会和沟通
  - 对"权力"没有兴趣
  - 无法接受"自己不做执行"的失落感
目标方向: 机械工程.md #19 技术经理/技术主管 (5年+), #20 技术总监/CTO (8年+)
```

### 模式 6: 制造业 → 互联网/科技行业

```
路径: [传统制造工程师] → [智能硬件/消费电子] → [科技行业]

前置条件: 0-3 年（越早越容易）

子路径 A: 行业平移（技能基本不变，只换行业）
  → 机械结构设计 → 消费电子/智能硬件结构设计
  → 工艺工程师 → 芯片厂/面板厂制造工程师
  → 技能重叠度 70%+，重点在理解新行业的流程和标准

子路径 B: 渐进跨界（需要补充新技能）
  → CAD/CAM 经验 → 图形学/3D引擎开发
  → 需要大量编程学习，适合 1-2 年经验的

总耗时: 3-12 个月（子路径 A）/ 1-2 年（子路径 B）
风险: 中低（子路径 A）/ 中高（子路径 B）
不适合:
  - 5 年+ 经验（行业知识壁垒变高，科技公司更愿意培养年轻人）
  - 对科技行业的工作节奏和文化不适应
目标方向: 机械工程.md 智能硬件/消费电子相关方向（行业平移，技能基本不变）
```

### 模式 7: 同行业跨职能（通用模式）

```
路径: [当前岗位] → [同行业不同职能] → [目标职能的深化]

前置条件: 在某个行业有 2 年+ 经验，对行业运作有基本理解
适用于所有行业，不限于制造业。

常见场景:
  → 运营 → 产品经理: 懂业务运作 + 补充产品方法论
  → 财务/会计 → 财务分析/FP&A: 技能重叠度 80%+
  → HR → 组织发展(OD): 从执行到设计
  → 客服 → 客户成功: 前端经验直接迁移
  → 编辑/内容 → 内容策略/增长: 从生产到策略

总耗时: 1-6 个月（行业内切换，学习曲线主要在方法论而非行业知识）
风险: 低
关键: 找交叉点——你现在的职能和目标的职能在什么场景下合作？
      从合作场景切入，而不是从零开始。

目标方向: 取决于具体行业和职能组合，无固定 career-path-map.md 映射
```

### 模式 8: 乙方→甲方（通用模式）

```
路径: [乙方/代理/服务商] → [甲方/客户方同职能]

前置条件: 在乙方有 2 年+ 经验，服务过甲方客户
适用于所有行业，是最高频的转行模式之一。

常见场景:
  → 事务所审计 → 企业财务: 考下 CPA + 甲方经验 = 稀缺组合
  → 咨询顾问 → 企业战略/总办: 方法论 + 行业聚焦
  → 4A 广告/公关 → 品牌方市场部: 从服务多客户到深耕一个品牌
  → 软件外包 → 互联网公司/甲方IT: 从"做项目"到"做产品"
  → 设计公司 → 企业设计团队: 从多行业快速出图到深度理解一个产品线

总耗时: 1-3 个月（职能不变，只需适应甲方工作节奏）
风险: 低-中（最大的风险是低估甲方的工作节奏和文化差异）
关键: 选对你的"甲方行业"——你在乙方服务过的行业中，哪个你最熟悉？
      从最熟悉的行业甲方开始，而非跳到完全陌生的行业。
不适合: 在乙方工作时间太长（8 年+）、已经适应乙方的多项目节奏、
        对"做一个产品做一年"感到无聊的人

目标方向: 取决于具体职能，无固定 career-path-map.md 映射
```

## 路径选择逻辑

```
技能重叠度 ≥ 70% → 直接路径
  [当前岗位] → [目标岗位]
  时间: 1-3 个月
  行动: 包装简历 + 投递 + 面试准备

技能重叠度 50-70% → 准备路径
  [当前岗位] → [补强技能 3-6 个月] → [目标岗位]
  行动: 补齐 Critical Path 技能后直接投递

技能重叠度 30-50% → 跳板路径（如果有匹配的跳板模式）
  [当前岗位] → [中间岗位] → [目标岗位]
  时间: 6 个月 - 2 年
  行动: 先找到中间岗位，在中间岗位积累目标方向的经验

技能重叠度 < 30% → 长期路径
  → 风险调节系数 < 1.0 + 财务缓冲充裕 → 可以尝试，选最接近的中间岗位开始
  → 风险调节系数 ≥ 1.2 → 建议在职学习，不裸辞
  → 四象限 Q3 → 强烈不建议，除非有极强的非转不可的理由

> 阈值定义与 gap-analysis-model.md Step D 保持一致。

## 时间线里程碑

### 模板

```
## 时间线: [当前岗位] → [目标方向]

### 3 个月
  [第一个里程碑 — 具体、可验证]
  例: 完成运动学在线课程 + 用 MATLAB 做一个 6 轴机械臂轨迹规划仿真
  验证: 能向一个机器人工程师讲清楚 DH 参数法和正逆运动学

### 6 个月
  [第二个里程碑]
  例: 完成一个物理 demo（如 3D 打印一个简易机械臂 + STM32 控制）
  验证: 作品可以放到简历上，能通过机器人公司的初筛

### 1 年
  [第三个里程碑]
  例: 拿到机器人本体设计岗的 offer，或进入机电一体化中间岗位
  验证: 薪资不低于当前水平（或降薪在可接受范围内）

### 3 年
  [长期目标]
  例: 成为机器人设计团队的核心成员，独立负责一个关节模块的设计
```

### 里程碑的设计原则

1. **每个里程碑有验证方式**——不只是"学完 X"，而是"能用 X 做出 Y"
2. **第一个里程碑最容易**——建立正反馈，避免"计划太大导致拖延"
3. **18 个月是一个心理阈值**——超过 18 个月的计划容易让人放弃，拆成两个子阶段
