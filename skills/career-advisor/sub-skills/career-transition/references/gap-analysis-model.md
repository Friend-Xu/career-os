# 差距分析模型

加权差距矩阵 + 优先级矩阵 + Cedefop 四象限 + 风险调节 + 财务建模。

---

## 一、加权差距矩阵

### Step A: 目标方向技能拆解

每个方向定义技能需求，分三级：

| 级别 | 含义 | 示例（机器人本体设计） |
|------|------|---------|
| **Critical（关键）** | 没有这个拿不到面试 | 3D机械设计(精通)、运动学/动力学基础(熟练)、传动机构设计(熟练) |
| **Important（重要）** | 有它优势明显，可入职后补 | 电机选型(熟练)、有限元分析(接触过)、机器人行业标准 |
| **Supporting（辅助）** | 锦上添花，不是必须 | ROS经验、多体动力学仿真、英语文献阅读 |

**权重**：Critical ×3、Important ×2、Supporting ×1

此命名与 LinkedIn Skills Mismatch Score 和 SkillGap 的业界通用术语对齐。

### Step B: 用户技能评级

| 等级 | 数值 | 标记 | 说明 |
|:--:|:--:|:--:|------|
| 精通 | 4 | ★★★ | 能独立解决复杂问题，能带人 |
| 熟练 | 3 | ★★ | 能独立完成常规工作 |
| 系统自学 | 2.5 | ★+ | 系统学过理论但缺实战。详见 skill-audit-guide.md |
| 接触过 | 2 | ★ | 学过或用过，不能独立完成 |
| 零基础 | 1 | — | 完全没接触过 |

> "系统自学"主要用于 gap 期间的知识映射（考研备考、系统培训等）。
> 与"接触过"的区别：接触过=随便学过一点；系统自学=完整学过但没机会用。

### Step C: 差距计算

```
差距分 = Σ(技能权重 × 等级差)

等级差 = max(目标要求等级 - 用户当前等级, 0)
        （用户超过要求时等级差 = 0，不加分也不减分）

最大可能差距分 = Σ(技能权重 × max(目标要求等级 - 1, 0))

  解释：只计入每个技能从"零基础(1)"到"目标要求等级"的实际差距。
  如果某技能目标要求=零基础(1)，则该技能不计入分母（max(1-1, 0)=0）。

标准化加权差距 = 差距分 / 最大可能差距分
```

### Step D: 技能重叠度

```
技能重叠度 = Σ(用户达标技能数) / Σ(目标方向总技能数)

  达标判定：用户等级 ≥ 目标要求等级

  重叠度 ≥ 70% → 可以直接投简历
  50-70% → 3-6 个月准备
  30-50% → 6-12 个月 + 可能需要中间跳板
  < 30% → 1 年+ 系统学习，基本算转行
```

### 边界敏感性标注

当技能重叠度落在阈值 ±5 个百分点内时，必须标注边界敏感性：

| 边界 | 敏感区间 | 标注内容 |
|------|:--:|------|
| 直接路径 vs 跳板路径 | 60% ±5%（即 55-65%） | "重叠度 XX% 靠近 60% 阈值。如果某项技能评级被下调（如面试中发现自己比预期的弱），可能跌入跳板路径区间。建议投简历的同时准备后备路径。" |
| 跳板 vs 长期学习 | 30% ±5%（即 25-35%） | "重叠度 XX% 靠近 30% 阈值。建议做一次实地面试测试——拿简历投 5 份试试，看市场怎么评价你的技能映射。" |

> 边界敏感性标注是为了防止用户因一两个技能评级偏差而做出过于乐观或悲观的决策。
> 评级本身有主观性，阈值附近不做非黑即白的判断。

### Step E: 有效工作年限

> 有效工作年限 = 实际工作月数 / 12（gap 时间不计入）。
> 经验因子对转行成本的影响详见 [Section 四 风险调节系数 - 因子 1](#因子-1-经验年限权重-35)。
> 此处不再重复定义调节值，两处数值保持同步。

## 二、差距 × 重要性优先级矩阵

决定"先补哪个技能"——不是所有 gap 都同等重要。

```
              │ Small Gap            │ Large Gap
              │ (等级差 = 1)          │ (等级差 ≥ 2)
──────────────┼──────────────────────┼──────────────────────
High          │ Quick Win            │ Critical Path
Importance    │ 2-4 周搞定            │ 3-6 个月重点投入
(Critical)    │ 例：学一个行业标准    │ 例：从零学运动学到熟练
              │ 优先做，建立信心      │ 转行成败在此
──────────────┼──────────────────────┼──────────────────────
Low           │ Defer                │ Ignore
Importance    │ 入职后再补            │ 不值得专门投入
(Important/   │ 例：熟悉机器人的ROS   │ 例：多体动力学仿真
 Supporting)  │ 面试时不关键          │ 锦上添花，先放一边
```

### 输出示例

```
## 技能补齐优先级: 机械设计 → 机器人本体设计

### Critical Path（必须先搞定）
  • 运动学/动力学 — 从"接触过"补到"熟练" | 预计 3-4 个月
    → 资源: Coursera "Modern Robotics" + 用MATLAB做6轴机械臂仿真
  • 传动机构 — 从"接触过"补到"熟练" | 预计 2-3 个月
    → 资源: 拆一个真实的工业机器人减速器 + 设计一个简易关节

### Quick Win（优先做，建立信心）
  • 了解机器人行业标准 — 1 周可搞定
    → 资源: 读 GB 11291-2011 + ISO 10218

### Defer（入职后再补）
  • 电机选型 — 有基础概念即可，入职后在项目中学习

### Ignore（不值得专门投入）
  • ROS编程 — 本体设计岗不需要，不要分散精力
```

## 三、Cedefop 四象限（适配版）

来源：Cedefop Career Bridge 方法论（2025）。
原始 Y 轴是"实际观察到的转行频率"（LinkedIn 数据），我们无此数据，
用 WebSearch 推断的**市场可观测性**替代。

### X 轴：技能重叠度（定量）

从一、Step D 的技能重叠度 % 取值。

### Y 轴：市场可观测性（定性·质量分级）

两步判定：

**第一步**: 搜索 `"[当前岗位] 转 [目标方向] 经验 路径 2025 2026"`

**第二步**: 对找到的案例做质量分级：

```
强可观测:
  ≥2 个招聘JD明确写"接受XX背景"/"XX背景优先"
  或 ≥3 个 LinkedIn/脉脉上可验证的真实转行案例（能看到实际工作变动时间线）
  或 该转行路径在行业中被广泛认可（如"机械→机电一体化→机器人"）

中可观测:
  有案例但主要是个人经验分享（知乎/小红书/公众号文章）
  无招聘JD验证，无法确认案例的真实性
  或 能找到 1-2 个案例但质量参差不齐

弱可观测:
  找不到实际案例，只有"理论上技能相通"的推理
  或 找到的案例条件与用户差距较大（如"某大佬从X转Y"但用户没有大佬的背景）
```

> 输出时标注来源类型和判定依据：
> `[强可观测·3个招聘JD+2个LinkedIn案例]`
> `[中可观测·2篇知乎分享·无JD验证，可能存在幸存者偏差]`
> `[弱可观测·无实际案例，仅基于技能相似度推理]`

### 四象限

```
              强可观测 ↑
                       |
    Q1: 软着陆          |    Q2: 顺滑过渡
   "低技能重叠但有人      |   "高重叠 + 市场验证充分"
    走通过"              |
                        |   策略：一步到位
   策略：中间跳板 or      |   直接投简历，重点包装
   内部转岗              |   技能映射关系
                        |
   例：机械设计→技术销售  |   例：机械设计→结构设计(消费电子)
   靠行业认知+沟通能力    |   几乎无缝
   不是技术深度          |
                        |
   ─────────────────────────────────────→ 技能重叠度
                        |
    Q3: 不建议           |    Q4: 隐形机会
   "低重叠 + 无案例"     |   "高重叠 + 少有人走"
                        |
   策略：回学校 or       |   策略：强故事线 + 直接投
   长期自学              |   竞争少但需要自己说服雇主
                        |
   例：会计→AI算法       |   例：机械设计→专利代理人
   需要重新读学位        |   技能上能转但少有人想到
                        |
              弱可观测 ↓
```

### 竞争强度修正

四象限策略基于技能重叠度和市场可观测性，但未考虑**竞争激烈程度**。
在输出四象限结果时，需叠加竞争强度修正：

```
竞争强度 = WebSearch 获取的竞争比（如"一个岗位 X 人竞争"）或从招聘量推断

  竞争比 < 10:1 → 不影响象限策略
  竞争比 10:1 - 30:1 → 象限策略不变，但标注"竞争激烈，简历需要差异化"
  竞争比 > 30:1 → 象限策略不变，但：
    - Q2 → 加注"虽然路径顺畅，但高竞争意味着仅'达标'不够，需要 Demo 项目或内推来突围"
    - Q1 → 加注"竞争激烈 + 技能有差距 = 中间跳板的优先级提升"
    - Q4 → 加注"隐形机会的窗口可能在缩小，加速行动"

数据来源优先级:
  1. WebSearch "[方向名] 竞争比 求职 招聘 2025 2026" → 直接获取
  2. 搜索 "[方向名] 招聘量 求职量 2025 2026" → 用招聘量变化推断
     （招聘量月增 > 20% + 求职量平稳 → 推断竞争比低；反之则推断竞争比高）
  3. 两者都不可得 → 跳过竞争强度修正，标注"竞争强度数据不可得，四象限策略不含竞争修正"
```

### 各象限策略

| 象限 | 转行方式 | 典型耗时 | 风险 |
|------|---------|:--:|------|
| Q2 顺滑过渡 | 直接投简历，重点包装技能映射 | 1-3 个月 | 低 |
| Q1 软着陆 | 找"愿意培养"的公司 + 中间跳板 or 内部转岗 | 3-12 个月 | 中 |
| Q4 隐形机会 | 强故事线 + 直接投，说服雇主"我能转" | 1-6 个月 | 中高 |
| Q3 不建议 | 回学校 or 长期自学。除非有极强的非转不可的理由 | 2 年+ | 极高 |

### 四象限与风险调节的优先级

**四象限定策略，风险调节定节奏。**

```
四象限告诉你"怎么转"（策略）
风险调节系数告诉你"用多快的速度转"（节奏）

例：Q1 软着陆 + 风险调节 = 0.84
  → "能转，可以用稍微激进的节奏（3-6个月目标）"

例：Q1 软着陆 + 风险调节 = 1.32
  → "能转，但必须用保守的节奏（在职学习，1年+时间线）"
  → 可行性评级从"可行但有代价"降到"困难但可能"
```

### 风险调节 ≥1.3 时的象限策略改写

当风险调节 ≥1.3 时（财务压力大），强制约束覆盖象限策略：

| 象限 | 原始策略 | ≥1.3 改写后策略 |
|------|---------|------|
| Q2 顺滑过渡 | 直接投简历 | **在职投简历**（不裸辞），利用年假面试 |
| Q1 软着陆 | 中间跳板 or 内部转岗 | **仅内部转岗或在职学习**，不裸辞找跳板岗 |
| Q4 隐形机会 | 强故事线 + 直接投 | 在职准备故事线和简历，**不裸辞** |
| Q3 不建议 | 回学校 or 长期自学 | **风险调节覆盖象限策略**。财务约束下 Q3 路径不可行。输出："该方向需要长期脱产学习，但你当前的财务缓冲不足。建议先解决财务缓冲（存够 12 个月生活费），或选择其他不需要脱产的方向。" |

> 原则：风险调节 ≥1.3 时，任何需要"裸辞"或"脱产"的策略都被改写为在职方案。
> 如果方向本身必须脱产（如回学校），则告知用户"先解决财务问题再考虑这个方向"。

## 四、风险调节系数

来源：Manning & Aguirre (2026), NBER WP 34705 的四因子模型，适配为三因子。

> 原模型含"地理密度"因子（就业加权平均 log(就业/面积)）。
> career-transition 因下游由 city-advisor 处理城市选址，将此因子从转行分析中移除，
> 避免与下游 skill 的功能重叠。用户做完转行分析后，用 city-advisor 确定目标城市。

### 因子 1: 经验年限（权重 35%）

| 有效工作年限 | 调节值 |
|:--:|:--:|
| 0-2 年 | 0.8 |
| 2-5 年 | 1.0 |
| 5-10 年 | 1.2 |
| 10 年+ | 1.4 |

### 因子 2: 财务缓冲（权重 40%）

| 存款覆盖月数 | 调节值 |
|:--:|:--:|
| 12 个月+ | 0.7 |
| 6-12 个月 | 0.9 |
| 3-6 个月 | 1.0 |
| < 3 个月 | 1.3 |
| 有负债（房贷等） | +0.2 叠加 |

> 财务缓冲权重最高（40%），因为它是转行决策中最硬的约束。

### 因子 3: 家庭约束（权重 25%）

| 约束 | 调节值 |
|------|:--:|
| 单身，地理自由 | 0.9 |
| 有伴侣，无孩，双方可协调 | 1.0 |
| 有学龄前子女 | 1.2 |
| 需要照顾父母 | 1.3 |

### 合成公式

```
风险调节系数 = 经验因子 × 0.35 + 财务因子 × 0.40 + 家庭因子 × 0.25
```

### 影响

| 系数范围 | 对可行性评级的影响 | 对路径推荐的影响 | 对财务模型的影响 |
|:--:|------|------|------|
| < 0.9 | 不降级 | 可以稍微激进 | 回本时间 × 风险调节系数 |
| 0.9-1.1 | 不降级（基准） | 标准推荐 | 回本时间 × 风险调节系数 |
| 1.1-1.2 | 原评级降一级 | 优先推荐"在职学习" | 回本时间 × 风险调节系数 |
| ≥ 1.2 | 原评级降一级 + 标注高风险 | 不推荐裸辞或脱产 | 回本时间 × 风险调节系数 |
| ≥ 1.3 | 强制"在职学习"或"内部转岗" | 裸辞/脱产选项不展示 | 回本时间 × 风险调节系数 + 标注"财务压力显著，回本时间仅供参考" |

> 回本时间统一使用 `回本时间 × 风险调节系数` 计算。风险调节系数本身已反映财务压力程度，
> 不需要再分档使用不同的乘法因子。≥1.3 时不改变公式但加注提醒。

## 五、财务模型

### 输入

```
不转行基线:
  当前年薪: X 万（用户自述 or 从职位+年限+城市推断，标注 [用户自述] 或 [推断]）
  年增长率: g%（搜索"[当前行业/方向] 平均涨薪 涨幅 2025 2026"获取，标注来源）
    如果搜索无果 → 使用保守默认值: 制造业 5-8%, 互联网 8-12%, 金融 8-15%
    标注 "[推断·默认值] 基于行业平均水平，未找到该方向特定数据"

转行后预测:
  目标方向起薪: Y 万（从 WebSearch 获取的社招数据，标注来源平台+年份）
  年增长率: h%（搜索"[目标方向] 薪资涨幅 发展前景 2025 2026"获取，标注来源）
    如果搜索无果 → 使用保守默认值（同行业基准），标注 [推断·默认值]
  转行成本: C 万（培训/学习/考证费用 + 可能的收入中断期）
```

> 涨薪假设是财务模型中最敏感的参数。g% 和 h% 的差值直接决定"回本时间"。
> 必须对每个增长率标注来源类型。如果两个都是默认值，财务模型的结论需加
> "涨薪数据不足，财务模型仅供参考"的声明。

### 五年累计比较

```
          基准情景                                保守情景（增长率×0.8,下限2%）
          Y1      Y3      Y5      5年累计        Y1      Y3      Y5      5年累计
不转行    X万     X'万    X''万    Σ不转行        X万     Xc'万   Xc''万  Σ不转行(c)
转行      Y万     Y'万    Y''万    Σ转行          Y万     Yc'万   Yc''万  Σ转行(c)
差额      Δ1      Δ3      Δ5      累计差          Δ1      Δ3(c)   Δ5(c)   累计差(c)

保守情景计算:
  g_保守 = max(g × 0.8, 2%)   [下限 2%，防止负增长或接近零]
  h_保守 = max(h × 0.8, 2%)

示例(g=8%, h=15%):
  基准: X×(1.08)²=1.166X   | X×(1.08)⁴=1.360X
  保守: X×(1.064)²=1.132X   | X×(1.064)⁴=1.282X  [8%×0.8=6.4%]
         Y×(1.15)²=1.323Y   | Y×(1.15)⁴=1.749Y
         Y×(1.12)²=1.254Y   | Y×(1.12)⁴=1.574Y  [15%×0.8=12%]
```

### 决策规则

```
基准+保守 5年累计差都 > 0:
  → "经济账算得过来——即使在保守情景下，转行也能带来正向收益。"

基准 > 0 但保守 < 0:
  → "经济账有风险——如果行业增速不及预期（保守情景），
    5年内可能无法回本。建议在职跳槽，不裸辞。"

基准+保守都 < 0:
  → "经济账算不过来。转行主要是非经济原因驱动（兴趣/成长/价值观）。
    确认这个方向是否值得承受经济代价。"

如果 g% 和 h% 都是默认值（非搜索验证）:
  → 只展示保守情景，标注"涨薪数据不足，仅展示保守估算"
```

> 保守情景的 0.8 系数来源: 金融规划行业惯例（SSA 三情景模型、
> FP Canada 敏感度分析均使用 20-30% 的乐观折扣）。
> 下限 2% 避免增长率接近零时出现不合理结果。

### 回本时间

```
回本时间 = 累计差额由负转正的时间点

如果回本时间 > 5年:
  → 标注"5年内无法回本，转行的经济账算不过来。
     如果仍要转，主要是非经济原因驱动。"

如果立即回本（转行起薪 ≥ 当前薪资）:
  → 标注"转行后薪资立即上涨，经济账立即为正。"
  → 风险调节系数不缩放回本时间（回本时间为 0，无缩放意义）。
  → 但财务缓冲风险仍需标注：若风险调节 ≥ 1.3，
    加注"虽立即回本但财务缓冲薄（<3个月），建议在职跳槽以确保平稳过渡。"
```

### 风险调节后的回本时间

```
如果回本时间 = 立即（0）:
  调节后回本时间 = 立即（不缩放）

否则:
  调节后回本时间 = 回本时间 × 风险调节系数
```
