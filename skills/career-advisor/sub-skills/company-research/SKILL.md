# 求职向公司背调
>
> 本文件是 career-advisor skill 的子模块。由主 SKILL.md 路由加载，不作为独立 skill 运行。

为求职者提供多维度的公司背景调查，根据职业定位动态调整分析重点。

## 依赖说明

本 Skill 依赖以下工具，缺失任一项都会影响搜索结果质量：

| 工具 | 来源 | 状态 | 说明 |
|------|------|:----:|------|
| `WebSearch` | Claude Code 内置 | 必选 | 中文搜索主通道，但实测**经常不可用**（返回 unavailable） |
| `WebFetch` | Claude Code 内置 | 必选 | 深度阅读招股书、官网等来源 |
| `Exa web_search_exa` | **ECC 插件内置 MCP** | 强烈推荐 | 语义搜索引擎，中文搜索结果质量远超 WebSearch，是本 Skill 的实际主力引擎 |
| `Exa crawling_exa` | **ECC 插件内置 MCP** | 推荐 | Exa 的全文抓取接口，token 消耗低 |
| `Agent` | Claude Code 内置 | 推荐 | 6轮搜索建议用 Agent 并行派发 |

### 如果你没有 ECC 插件

Exa MCP 需要 API Key。如果你没有安装 ECC，需要自行配置：

1. 在 [exa.ai](https://exa.ai) 注册免费账号获取 API Key
2. 在 `~/.claude.json` 或项目 `.mcp.json` 中添加 Exa MCP Server：

```json
{
  "mcpServers": {
    "exa": {
      "type": "http",
      "url": "https://mcp.exa.ai/mcp",
      "headers": {
        "Authorization": "Bearer <your-exa-api-key>"
      }
    }
  }
}
```

### WebSearch 不可用时的降级策略

`WebSearch` 工具实测可用性不稳定。如果搜索返回 `unavailable`：
1. 将全部搜索负载转移到 Exa（中英文混合搜索）
2. 报告末尾标注"本次搜索 WebSearch 不可用，部分中文源（知乎/看准/牛客）未被检索"
3. Tier 2 中文源（知乎/看准/牛客网）移入 Tier 3 自查清单

## 工作流程总览

```
Step 0: 查档确认对象 → 读 companies/，识别已有档案（占位/尽调/别名）
Step 1: 三问定框架 → 阶段 + 职业 + 关心维度
Step 2: 确认 + 职业推理 → Read references/career-inference.md
Step 3: 搜索执行      → Read references/search-strategy.md
Step 4: 深度阅读      → WebFetch 3-5篇高价值来源
Step 5: 对抗验证      → Read references/adversarial-review.md
Step 6: 输出报告      → Read references/report-template.md + references/interview-questions.md
Step 7: 收尾          → Read assets/tier3-user-checklist.md
```

---

## Step 0: 查档确认对象（Company Artifact Admission）

**先查 companies/ 目录，再开始任何工作。** 公司档案是系统身份资产——同一主体只允许一份档案，
禁止重复建档（一个主体的两份 markdown = 身份分裂，UI/图谱会把它们当成两家公司）。

```
输入: company_name_candidate（用户给的或 JD 里的公司名）

流程:
  1. 列出 companies/ 目录（Read/Glob）
  2. 精确匹配 canonical name（文件名）
  3. 匹配既有 aliases（档案摘要表 `aliases` 行的名称）
  4. 命中 → 本次尽调针对该档案：档案名、已有字段、占位还是已尽调
  5. 无匹配 → 本次尽调将新建档案，落盘时用与既有命名习惯一致的名称
```

关键判断：

- **已存在占位档案（摘要表其余字段为 `-`，正文含「占位档案」）** → 本次尽调**升级该档案**：
  Step 6.5 落盘时写回同一个文件名，不创建新文件。占位档案是 JD 建档自动创建的
  （文件名 = 建档时用的名称，可能是简称）。
- **档案名称与用户/JD 名称不一致（简称 vs 全称）** → 落盘时以既有档案名为准（汇川技术、
  南京新拓尼克、嘉树医疗均为业务名，不是工商全称），同时在摘要表 `aliases` 行登记本次
  使用的其他称呼（Agent 提议 → 引擎校验登记，消费端按 alias 精确解析）。
- **禁止**:已存在主体时创建第二份公司 markdown。

## Step 1: 三问定框架

如果用户没有直接提供完整信息，依次问以下三个问题。

### 问题一：阶段

```
你现在是什么阶段？
A. 海投筛选 → 快速判断值不值得投，重点赛道+稳定性
B. 面试中   → 补全认知，准备面试反问
C. 拿到offer → 深度背调，重点风险+口碑+薪资对标
D. 纯了解   → 全面但不啰嗦
```

### 问题二：职业定位

```
你的职业定位是什么？（自由输入）
例如："机械工程师"、"Java后端开发"、"新能源电池工艺工程师"、
"跨境电商运营"、"还没定方向"
```

用户输入后，Read `references/career-inference.md`，根据推理引擎分析该职业的关注维度。

### 问题三：关心维度（可多选）

```
你最关心什么？
A. 薪资待遇水平
B. 公司稳定性/会不会裁员
C. 加班文化和团队氛围
D. 技术成长空间
E. 都关心（全维度）
```

如果用户在前面已表达了关切倾向，跳过此问，直接确认。

---

## Step 2: 确认 + 职业推理

将用户的回答总结为一段确认语，同时 Read `references/career-inference.md` 完成职业推理。

确认语示例：
> "收到。你是拿到offer的机械工程师，最关心稳定性和技术成长。
> 针对机械工程师，我会重点看：
> 1. 公司主营业务是否匹配机械岗（是不是核心职能）
> 2. 近三年财务健康度（会不会裁）
> 3. 研发投入和技术团队规模
> 4. 员工对技术氛围的评价
> 开始查。"

---

## Step 3: 搜索执行

Read `references/search-strategy.md` 获取搜索模板。

### 核心原则

1. **三层分级**：Tier 1 必查（公开可及）→ Tier 2 尽力（缓存/收录不确定）→ Tier 3 指路（需用户自己查）
2. **职业驱动调词**：搜索词根据用户职业自动增减（如机械工程师加"研发投入 专利 技术团队"）
3. **并行搜索**：6轮搜索同时进行（WebSearch + Exa 双源）

### 搜索执行清单

| 轮次 | 维度 | 完成 |
|:----:|------|:---:|
| 1 | 公司基本面 | ☐ |
| 2 | 财务/上市状态 | ☐ |
| 3 | 员工口碑 | ☐ |
| 4 | 薪资+岗位面经 | ☐ |
| 5 | 法律风险 | ☐ |
| 6 | 行业地位 | ☐ |

每轮 2-3 个关键词变体。

---

## Step 4: 深度阅读

搜索完成后，挑选 3-5 个高价值来源全文阅读：
- **招股书/年报第一**（交易所公告、财经网站PDF）
- **深度报道第二**（行业媒体、财经分析）
- **面经/口碑第三**（牛客网、知乎缓存页）

---

## Step 5: 对抗验证（草稿→审查→终版）

Read `references/adversarial-review.md`。

**5.1 先写报告草稿**：基于搜索和深度阅读结果，按 report-template.md 模板生成完整草稿。

**5.2 以反方视角逐条审查**：
- 是否把管理层叙事当成了事实？
- 是否用单一指标推出强结论？
- 是否存在能推翻当前判断的反证？
- 职业视角是否贯穿始终？
- 信息缺口是否诚实标注？

**5.3 修正后输出终版**：发现的问题修正后再输出最终报告。不得跳过草稿阶段直接输出。

---

## Step 6: 输出报告

Read `references/report-template.md` 获取完整模板。
Read `references/interview-questions.md`，根据 **career-inference.md 推断的职能类型**（研发/制造/销售/运维/管理/不确定），从 interview-questions.md 中选择对应模板，填入报告 3.5「面试反问十问」章节。

**先输出精简摘要（200字以内），再输出完整报告。**

精简摘要包含：一句话判断、适合的点、需要注意的点、建议。

完整报告包含七个章节：
1. 公司基本面
2. 财务与资本
3. 职业视角分析（含面试反问十问）
4. 员工口碑与公司文化
5. 法律与合规风险
6. 行业与竞争
7. 综合判断 + 最终建议

---

## Step 6.5: 落盘公司档案

Read `references/company-file-contract.md`，将尽调结论落盘为 `workspace/career-advisor/companies/{公司名}.md`：`## 分析摘要` 表（字段值格式严格，match_score 只写 `85%`/`8.2/10`、tags 逗号分隔、contacted 未联系写「否」）+ `## 尽调详情` 正文。引擎监听该目录，写完自动感知并通知 UI，无需手动操作。

**落盘文件名 = Step 0 查档结果**：命中既有档案（含占位）→ 写回**同一个文件名**（升级，不新建）；
无匹配 → 新建。名称与档案名不一致时，把其他称呼登记进 `aliases` 行（逗号分隔）。

**顺带写 `## 公司事实` 段**（Company Intelligence v0.1——职业价值评估的输入，规则见 company-file-contract.md「公司事实段」小节）：
- 把尽调搜索中**已获取**的信号结构化落盘为 4 列表格（类型/内容/来源/链接）：专精特新/高新技术企业、融资轮次、核心专利、招聘活跃、经营风险
- 内容必须 ∈ 评估契约 value 枚举（`references/company-assessment-contract-v0.1.md` §4——枚举外不计分）；**来源必填**（外部公开渠道，缺来源不计分）
- **禁止编造信号凑分**：尽调没查到的信号不写（无可用信号 → 不写该段 = 待评估，诚实状态；后续尽调补充时更新该段）
- 写完摘要表/尽调详情/事实段后，引擎自动检测 → 计分 → UI 职业价值展示，无需手动操作

---

## Step 7: 收尾

报告末尾，Read `assets/tier3-user-checklist.md`，输出用户需要自己去确认的事项清单。

**岗位入库（Roles 生产契约）**：尽调确认公司在招岗位时（如公司官方在招、JD 可见），把岗位登记进
`workspace/career-advisor/knowledge/roles.md`——格式与 Producer Boundary 见
`../../references/roles-contract.md`（`## 岗位名（公司名）` + 技能需求，来源标 `公司档案-{公司}`）。
岗位清单是公司岗位实例库：技能需求必须能从尽调文档回溯，禁止写文档之外的泛化技能；
同公司同名岗位已登记则更新不重复建。

然后问一句：
> "还想深挖哪个方面？"

## 边界情况

### 公司名模糊
先确认全称和城市，存在多家同名时列出选项让用户确认。

### 完全搜不到
诚实告知，至少输出工商基本信息（如果搜到的话）。标注：信息极少，这本身就是一条重要信息（可能是空壳/极小微公司）。

### 非上市公司
主要靠口碑和招聘信息，财务数据标注"未公开"，不瞎编。

### Offer 对比
"帮我对比A和B"→ 两轮独立搜索 → 输出并排对比表 → 给出倾向性建议。

### 无职业定位
用户说"还没定方向"→ 跳过职业调校 → 全维度通用报告。

---

## 质量规则

1. 每条信息标注来源类型：官方文件 / 媒体报道 / 个人评价 / AI推断
2. 匿名评价标"仅供参考"，官方文件标"可信"
3. 查不到就说查不到，不编造
4. 区分事实和推断：财务报表是事实，行业趋势是推断
5. 旧数据标年份，提醒可能已变化
6. 报告始终围绕用户职业定位组织
7. SKILL.md 正文控制在 500 行以内，详细规则放在 references/
