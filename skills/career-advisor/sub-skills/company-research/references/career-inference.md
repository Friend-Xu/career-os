# 职业推理引擎

## 推理逻辑

用户自由输入职业名 → AI 从三个维度当场推理，不需要预设职业列表。

---

## 维度一：职能类型判断

根据职业名中的关键词，判断职能大类：

| 职能类型 | 典型职业名关键词 |
|----------|-----------------|
| **研发/技术类** | 工程师、研发、开发、设计、算法、架构、科学家、程序员 |
| **制造/工艺类** | 工艺、制造、生产、质量、检测、装配、设备、操作 |
| **销售/市场类** | 销售、客户经理、BD、市场、营销、渠道、商务、售前 |
| **运维/支持类** | 运维、技术支持、网管、IT、系统管理员、测试、客服 |
| **管理/职能类** | 经理、主管、总监、HR、人力资源、财务、行政、法务、采购 |
| **不确定** | 职业名太新/太小众，进入追问模式 |

## 维度三：核心关注点映射

### 研发/技术类 → 重点关注

1. **公司是不是"真研发"**
   - 研发投入占比（vs 同行）
   - 发明专利数量（vs 实用新型/外观）
   - 是否有核心技术壁垒
2. **技术成长空间**
   - 技术路线是否符合行业方向
   - 团队规模和导师机制
   - 产品复杂度（是核心产品还是边缘功能）
3. **技术岗话语权**
   - 创始人/高管是否技术出身
   - 研发人员占比
4. **关键风险**
   - 公司是"自研"还是"抄作业/集成商"
   - 技术栈是否过时
   - 岗位天花板（是否核心部门）

### 制造/工艺类 → 重点关注

1. **制造能力**
   - 是否有自主工厂（vs 代工）
   - 设备先进度
   - 产线自动化水平
2. **工作条件**
   - 加班/倒班制度
   - 工作环境（恒温/噪音/粉尘）
   - 安全记录
3. **工艺技术可迁移性**
   - 在此学到的技能在其他公司是否通用
4. **关键风险**
   - 产线外迁或自动化替代
   - 纯代工无技术含量
   - 行业产能过剩

### 销售/市场类 → 重点关注

1. **销售模式**
   - 技术型销售（顾问式） vs 关系型销售 vs 电话销售
   - 底薪 vs 提成比例
   - 是否需要自己开拓客户
2. **工作强度**
   - 出差频率
   - 业绩考核压力
   - 客户资源质量
3. **公司市场地位**（影响销售难度）
   - 公司在行业中的品牌影响力
   - 产品竞争力和定价权
4. **关键风险**
   - 纯关系销售（可替代性高）
   - 指标过高或不合理
   - 行业回款周期长

### 运维/支持类 → 重点关注

1. **是否是核心部门**
   - IT/运维在公司的地位
   - 是自己团队还是外包
2. **基础设施投入**
   - 技术栈现代化程度
3. **关键风险**
   - 被外包化
   - 边缘化、无晋升通道

### 管理/职能类 → 重点关注

1. **公司治理**
   - 家族企业还是职业经理人
   - 组织架构清晰度
2. **福利体系**
   - 五险一金缴纳基数
   - 年假、病假、年终奖
3. **稳定性**
   - 公司财务健康度
   - 行业景气度

## AI 拿不准时的追问模板

当职业名过于小众/新潮，AI 无法归类时，用带判断的追问：

```
不是："你什么意思？"
而是：
"我理解'自动驾驶感知算法工程师'比较关注：
  R&D投入、硬件计算平台、算法团队规模。
  这理解对吗？另外你最看重薪资 / 技术成长 / 团队氛围哪方面？"
```

---

## 无职业定位 → 全维度通用模式

用户说"还没定方向"→ 跳过职业调校，六个维度等权重输出通用报告。

报告中不出现"职业匹配度速评"章节，改为"通用概况"。
