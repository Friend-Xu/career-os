# Frontier 追问引擎

resume-writing 的核心。基于 batch-grill-me 的 frontier 模型 + grilling 的推荐答案规则。

---

## 一、引擎总览

```
用户输入一段工作描述
  ↓
【模糊信号检测器】扫描 → 构建信息缺口列表
  ↓
每轮：
  1. 区分缺口类型（事实缺口 vs 决策缺口）
  2. 事实缺口 → agent 自己查（profile/decisions/简历文件），查到即填
  3. 决策缺口 → 计算 frontier（互不依赖的缺口）
  4. 每个 frontier 缺口 → 生成一个单一问题 + 推荐答案
  5. 等用户回答 → 更新缺口列表 → 下一轮
  ↓
frontier 为空 → 追问结束 → 进入 STAR 重构
```

### 终止条件

```
frontier 为空 = "系统有足够信息能独立写出简历的所有部分，不需要再追问"

具体判定：
  ✓ 每段工作经历至少有 3 个不同的具体行为描述
  ✓ 全简历至少有 2 个量化结果（精确值或用户确认的估计值）
  ✓ 所有被"模糊信号检测器"标记的模糊点已消除
  ✓ 教育/技能/证书等基本信息已填充

不满足 → frontier 不空，继续追问
```

### 最多追问轮数

不设硬上限。但如果超过 5 轮且 frontier 仍不为空：
```
"我们聊了挺多，我先基于已有信息写一版初稿。
 标出我还不确定的几处，你看看哪些可以补充。"
```

## 二、模糊信号检测器

逐条扫描用户输入，匹配模糊信号 → 创建对应的信息缺口。

### 信号检测表

| 信号 | 检测词/模式 | 创建的缺口 |
|------|-----------|----------|
| 职责模糊 | "负责"、"承担"、"主要做" 后无具体动作 | 职责细节缺口 |
| 贡献不确定 | "参与"、"配合"、"协助"、"支持" | 职责细节缺口 |
| 无量化 | 段落中无数字（百分比/金额/天数/人数） | 量化结果缺口 |
| 只说了过程 | "做了"、"完成了"、"处理了" 后未跟结果 | 量化结果缺口 |
| 只有常规 | "日常"、"每天"、"常规工作"、描述全是日常流程 | 例外突破缺口 |
| 管理模糊 | "带过人"、"管团队"、"负责团队" 未说规模和方式 | 管理经验缺口 |
| 协作模糊 | "协调"、"对接"、"沟通"、"拉通" 未说对象和难度 | 协作细节缺口 |
| 描述平淡 | 整段无"最"、"第一次"、"被表扬"、"得奖"等亮点词 | 个人定位缺口 |
| 多段孤立 | 两段及以上经历，各段独立描述无关联 | 主线关联缺口 |

### 信号优先级

同一个人口述中通常同时出现多个信号。按优先级排序：

1. **职责细节** — 最基础，不搞清楚后面都白搭
2. **量化结果** — 简历质量的直接体现
3. **例外突破** — 通常隐藏最大价值
4. **管理经验 / 协作细节 / 个人定位** — 增强区分度
5. **主线关联** — 最后再串（要等其他缺口填完才能提取主线）

## 三、7 类缺口定义

### 缺口 1：职责细节

**触发**：检测到"负责/参与/协助/承担/主要做"

**缺口定义**：不知道用户具体做了什么、贡献占比、用的是哪些工具/方法

**事实部分（agent 自己查）**：
- career-transition 技能画像中是否已有该职责的映射
- 上传的简历中是否有相关描述

**决策部分（问用户）**：

通用追问模板：
> "你说'[用户原话]'。我猜测你的具体贡献是 **[基于已有信息的推断]**——对吗？还是团队一起做的？"

推断规则：
- 从岗位名称推断 → "你是做机械设计的，我猜主要是三维建模和出工程图"
- 从行业上下文推断 → "你在汽车零部件行业，应该是接触过APQP流程"
- 从前一条回答推断 → "你刚才说良率提到96%，我猜是你主导的改进"

如果无法推断 → 开放式的：
> "你说'负责产线异常处理'——能不能具体说说：最近一次异常是什么情况、你做了什么、结果怎样？"

### 缺口 2：量化结果

**触发**：段落中无数字 / 检测到"做了/完成了/处理了"

**缺口定义**：不知道这件事的规模、影响、频率

**事实部分（agent 自己查）**：
- 无。量化结果只能来自用户口述。
- **方向卡锚点**：如果可识别目标方向，读 `references/direction-standards/{方向名}.md` 的量化指标锚点表——优先用该方向的锚点类型做推荐答案

**决策部分（问用户）**：

通用追问模板：
> "你说'[某事]影响很大'。我猜测影响体现在 **[基于行业常识的推断]**——哪个方向？大概什么量级？"

推断规则：
- 优先从方向卡的量化指标锚点表中选择匹配的锚点类型
- 次选从行业常见指标推断：
  - 制造业 → 良率/废品率/交付周期/成本节省
  - 软件 → QPS/响应时间/用户数/故障率
  - 销售 → 签单额/客户数/回款周期/转化率
  - 教学 → 成绩变化/课程数/评教分数
  - 医疗 → 手术量/并发症率/患者满意度
  - 营销 → 曝光量/转化率/获客成本
- 从用户已有描述推断范围 → "大概省了几万块？还是几十万？还是上百万？"
- 无法推断 → 开放式的："有没有具体的数字可以说明这件事的结果？哪怕是个大概范围"

### 缺口 3：例外突破

**触发**：描述全是日常/常规/流程性工作

**缺口定义**：不知道用户在日常之外做了什么超出职责的事

**事实部分（agent 自己查）**：
- 无。例外经历只能来自用户口述。

**决策部分（问用户）**：

> "除了日常的[XX工作]，有没有过这种情况：
>  **同事请假你顶上了某块工作**、或者**处理过什么紧急情况**、
>  或者**你做了一件不在你职责范围内但后来被认可的事**？
>  比如带过新人、写过一份后来被沿用的文档/流程——这些事往往比日常工作更值得写。"

### 缺口 4：管理经验

**触发**：检测到"带过人/管团队/负责团队"

**缺口定义**：不知道管理方式（直接/虚线）、管理规模（几人）、管理行为（打绩效/培训/分配工作）

**事实部分（agent 自己查）**：
- 技能画像中的"项目与流程管理"分类

**决策部分（问用户）**：

> "你说带过团队。是**直接带人（打绩效/分配活儿/面试招人）**，
>  还是**虚线带项目（临时拉人干活但不打绩效）**？
>  大概几个人？什么级别？

>  另外，**有没有培训过新人**？正式/非正式的都算。"

### 缺口 5：协作细节

**触发**：检测到"协调/对接/沟通/拉通"

**缺口定义**：不知道协作对象、协作难度、冲突解决

**事实部分（agent 自己查）**：
- 技能画像中的"沟通与人际"分类

**决策部分（问用户）**：

> "你说协调了多方。我猜测是**跨部门的——研发+生产+采购**，
>  还是**和外部的供应商/客户**？最难协调的一次是什么情况？
>  有没有过**争执不下的场景，你最终怎么推动的**？"

### 缺口 6：个人定位

**触发**：整段经历描述平淡，无独特价值信号

**缺口定义**：用户不知道自己区别于同行的价值

**事实部分（agent 自己查）**：
- 技能画像中标注了"精通 ★★★"的技能
- 用户 profile 中的弱项（反向信号：弱项的另一面可能是"我做不好这个但我擅长那个"）

**决策部分（问用户）**：

> "如果明天你离职了，同事聚餐时说起你，会说
>  '可惜了，公司里没人能像他一样 **[XX]** 了'——
>  我猜 XX 可能是 **[基于已有信息的推断]**。
>  你觉得 XX 是什么？

>  另一个角度：**你和同期入职的同事比，有什么不同？**"

推断规则：
- 从量化结果推断 → "你良率提到96%，可能在这个领域你是最快的"
- 从例外突破推断 → "你能快速定位夹具问题，这可能是你的独特优势"
- 无法推断 → 开放式的

### 缺口 7：主线关联

**触发**：两段及以上工作经历

**缺口定义**：不知道几份工作之间的内在逻辑——用户是"乱跳"还是"有方向地积累"

**事实部分（agent 自己查）**：
- 技能画像中的行业领域变化
- profile 中的目标方向

**决策部分（问用户）**：

> "你从 [公司A] 到 [公司B]，我注意到一条线：
>  **[基于已有信息的推断]**——这个判断对吗？还是我想偏了？"

推断规则：
- 同行业不同公司 → "你一直深耕[XX行业]，只是换了平台"
- 不同行业相似岗能 → "虽然行业变了，但[XX技能]一直在用，而且越来越深"
- 岗位越来越 senior → "你一直在往[XX方向]走，每跳一次提升一级"
- 找不到规律 → "几段经历看起来方向不太一样——是**每段都是因缘际会到了就去**，还是**有什么共同的东西你还没说出来**？"

## 四、事决分离

### Agent 自己查的事实清单

在执行每轮 frontier 追问之前，先查以下来源，能查到的缺口直接填掉，不占用本轮问题配额：

```
查找顺序：
  1. workspace/career-advisor/profiles/{用户名}.md         ← 已有基本信息/技能画像/目标方向
  2. workspace/career-advisor/decisions/*.md               ← 已有决策（避免重复问）
  3. 用户上传的简历文件内容                                 ← 已有简历的字段
  4. workspace/career-advisor/INDEX.md                     ← 当前状态

如果 profile.md 不存在 → 问用户（一次性收集）：
  - 当前岗位 / 工作年限
  - 学历 / 专业
  - 当前城市
  这 3 个问题放在 Step 1（信息收集），不算在 frontier 轮次内。
```

### 只能问用户的决策型缺口

```
必须问用户（不做假推断）：
  ✗ 某段经历要不要写进简历（用户的选择）
  ✗ 某个弱点要不要在简历中体现（用户的风险偏好）
  ✗ 目标方向是什么（用户的主观意愿）
  ✗ 数字的估计（"大概几万？"）
  ✗ 主观价值判断（"这件事你做得比别人好吗？"）
```

## 五、推荐答案生成规则

每个 frontier 问题必须附带推荐答案。生成规则：

### 有推断依据时

```
模板："[问题]。我猜测是 **[推荐答案]**——对吗？还是其他？"

推断来源（按可靠性排序）：
  1. 用户前面轮次已经说过的话
  2. 用户的岗位名称/行业（常见的成果方向）
  3. profile.md 中的技能画像
  4. 行业常识（制造业→良率/成本；软件→性能/用户量；销售→签单额）
```

### 无推断依据时

```
模板："[开放式问题。给出2-3个选项降低用户思考负担]"

例："你说这个项目影响很大。最可能的方向是哪个？
      - 良率/质量提升
      - 成本节省
      - 交付时间缩短
      - 其他（你说）"
```

### 不适用推荐答案时

以下情况不生成推荐答案，直接问事实：
- 用户的基本信息（姓名/电话/邮箱）——这是事实采集不是决策
- 用户明确说了"我记不太清了"——不要硬猜
- 涉及可能的造假（"你大概做了X年吧？"）——让用户自己说

## 六、frontier 计算规则

每轮开始前，扫描所有未填缺口，计算哪些可以同时问：

```
frontier = 所有满足以下条件的缺口：
  1. 缺口未被标记为"已填"
  2. 缺口的所有前置缺口已填（不依赖其他未填缺口）
  3. 缺口是决策型（事实型已被 agent 填掉）

前置依赖规则：
  - 职责细节 → 量化结果（先知道做了什么，才能问结果）
  - 职责细节 → 例外突破（例外是职责的延伸）
  - 量化结果 → 个人定位（量化结果是个人定位的素材）
  - 以上都填完 → 主线关联（所有素材齐了才能串主线）
  管理经验、协作细节 → 互不依赖，可同时出现在 frontier

每轮 frontier 问题不超过 5 个。超过的按优先级排序，低优先级的留到下一轮。
```

---

## 七、追问终止判断

每轮用户回答后，重新计算：

1. 逐条检查所有缺口 → 标记已填/未填
2. 检查是否满足终止条件（第一节定义）
3. 满足 → 结束追问
4. 不满足 → 计算新的 frontier → 继续

如果用户说"够了，先写吧" → 尊重，立即结束。但提示：
```
"好的，我先基于已有信息写。标出我不确定的几处（如量化结果、管理经验），
 你看看后续要不要补。"
```
