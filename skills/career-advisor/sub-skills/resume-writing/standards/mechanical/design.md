# Design Language — Mechanical

> 语言族 ID：mechanical.design
> 锚定岗位：机械结构设计 / 模具设计 / 机器人本体结构 / 医疗器械结构
> 标准版本：CareerContentStandard v1.3（契约：docs/contracts/CareerContentStandard-v1.md）
> 来源：12 岗位 JD 调研（2026-08-03，docs/career-content/research/mechanical/design.md）+ 旧 direction-standards 数据迁移（2026-08-03，已复核）
> 修订（2026-08-13，v1.3）：撰写规范调研（writing-norms.md）——量化锚点可得性标注 + 「负责」警示 + 样机专项结构

## 1. 语言族定位（Purpose）

本语言族表达**方案设计能力**：从需求到可交付设计方案的完整闭环。
核心能力链：结构方案设计 → 详细设计（建模/出图）→ 验证（仿真/样机）→ 量化影响。

## 2. Signal Coverage

### 2.1 Quality Signals（表达完整性）

| 信号 | Required | 本语言族含义 | Verification Rule |
|------|:--:|------|------|
| Q1 Object | Yes | 明确的结构对象（整机/部件/机构/关节模组/模具） | 具体名词；"设备/结构件"泛称不达标 |
| Q2 Method | Yes | 设计方法与工具（软件/工艺/标准/选型手段） | 具体到工具名（SolidWorks/ANSYS/DFM/公差分析） |
| Q3 Validation | Yes | 验证闭环（仿真校核/样机测试/DV 验证/量产验证） | 有动作有载体（样机/试验/报告/评审） |
| Q4 Impact | Preferred | 量化影响（减重/成本/寿命/频率/应力） | 指标名 + 数值 + 方向，且绑定 Q1 对象 |
| Q5 Scope | Optional | 全流程跨度（方案→量产 / 跨部门协作） | 有边界描述（从 X 到 Y / 对接 N 部门） |

### 2.2 Mandatory Signals（行业硬约束）

| 类别 | 信号 | 覆盖规则 |
|------|------|---------|
| 通用 | GD&T、DFM/DFA、DFMEA、FEA（ANSYS/Abaqus）、材料选型、公差分析 | 自然证据覆盖，堆词不加分 |
| 软件 | SolidWorks、Creo、UG/NX、CATIA、AutoCAD | 至少一种在项目描述中出现 |
| 工艺 | 注塑/冲压/压铸/钣金/机加工、模具结构 | 与设计对象绑定的工艺约束 |
| 医械增补（Domain Constraint） | ISO 13485、ISO 14971、ISO 10993、DHF/DMR、NMPA/CE/FDA | 只增信号条目，不改变 Q1-Q5 结构 |

## 3. 信号标准（Q1-Q5 实例化）

### Q1 Object

**Purpose**：明确的工程对象使经历可验证、可追问。

**Required Evidence**

| Evidence | Required | Example |
|----------|----------|---------|
| 对象类型 | Yes | 整机/部件/机构/关节模组/模具 |
| 对象名称 | Yes | 机械臂末端执行器、谐波减速器、Project-A 生化分析仪 |
| 规格/约束 | Preferred | 二类/三类有源器械、额定载荷 X kg、节拍约束 |

**Weak Example**："负责机械结构设计，提高产品性能。"

**Strong Example**："独立完成机器人关节模组结构设计（谐波减速器 + 无框力矩电机集成），满足额定负载 X kg 与背隙 ≤Y′ 要求。"

**Verification Rule**：对象必须是具体名词，可对应实际产品或部件；"设备/系统/结构件"泛称不达标。

**Confidence**：High

### Q2 Method

**Purpose**：具体的方法与工具证明能力可执行、可迁移。

**Required Evidence**

| Evidence | Required | Example |
|----------|----------|---------|
| 工具 | Yes | SolidWorks 建模、ANSYS Workbench 静力学、DFM 评审 |
| 方法 | Yes | 拓扑优化、公差分析、DFMEA、材料选型 |
| 标准 | Preferred | GD&T、ISO 13485、IATF 16949 |

**Weak Example**："进行了大量结构优化工作。"

**Strong Example**："基于 ANSYS 完成拓扑优化并叠加制造工艺约束，确定铸改铝型材焊接方案。"

**Verification Rule**：方法必须有工具/标准载体；"优化/分析"无载体词不达标。

**Confidence**：High

### Q3 Validation

**Purpose**：验证闭环证明结论可信，是"设计了"与"设计并验证了"的分界。

**Required Evidence**

| Evidence | Required | Example |
|----------|----------|---------|
| 验证动作 | Yes | 样机打样、跌落/防水/疲劳测试、DV 验证、试产 |
| 验证载体 | Yes | 样机、试验报告、测试数据 |
| 结果判定 | Preferred | 通过标准（满足 X 标准 / 无失效） |

**Weak Example**："产品经过测试后投入量产。"

**Strong Example**："主导样机 DV 验证（强度/密封/IP 防护），测试通过率 100%，满足 IEC 60601 安规要求。"

**Verification Rule**：验证必须有载体（样机/试验/报告）；"经过测试"无载体词不达标。

**Confidence**：High

### Q4 Impact

**Purpose**：量化影响是 Design 语言族最强的职业信号——证明优化有效而非空泛表态。

**Required Evidence**

| Evidence | Required | Example |
|----------|----------|---------|
| 指标名 | Yes | 重量、成本、疲劳寿命、固有频率、应力、噪音 |
| 数值 | Yes | 减重 15%、成本降 17.6%、寿命 5万→8.5万次 |
| 方向 | Yes | 降低/提升（与指标语义一致） |
| 绑定对象 | Yes | 作用于 Q1 的对象 |

**Weak Example**："显著提升了产品性能。"

**Strong Example**："通过拓扑优化将电池托盘减重 8.5kg（-15%），并通过强度与挤压仿真验证。"

**Verification Rule**：Impact 必须绑定 Q1 对象（"减重 15%"须说明减谁的重量）；无指标名的"提升 X%"不达标。

**Impact Evidence Hierarchy**（无数值时的表达层级，不允许跨级推导）：

| Level | 类型 | 示例 | 证据要求 |
|:--:|------|------|---------|
| L1 | 明确量化 | 降低 20% / 缩短 30% / 减重 8.5kg | 数值 + 指标名 + 对象 |
| L2 | 范围化/阶段化 | 减少装配复杂度 / 提升可靠性 / 完成验证闭环 | 有范围或阶段描述 |
| L3 | 事实结果 | 通过测试验证 / 满足设计要求 / 完成客户验收 | 仅事实 |

规则：**不得从 Level 3 推导 Level 1**（"完成测试验证" ≠ "提升可靠性 20%"）；基线无数值且无范围证据时，允许 L2/L3 表述并标注"建议追问量化"。

**可得性档位规则（v1.3）**：业务结果（成本/营收）不可得 → 落交付物/工程指标档（图纸量/减重/寿命/频率——自测所得）；结果未知 → 写确定性终点（完成交付/通过验收/进入量产）；**无证据数字 = 最严重违规**。

**Confidence**：High

### Q5 Scope

**Purpose**：职责跨度证明独立性与系统能力。

**Required Evidence**

| Evidence | Required | Example |
|----------|----------|---------|
| 流程跨度 | Yes | 从方案到量产全流程 |
| 协作范围 | Preferred | 与工艺/电气/采购跨部门对接 |
| 独立程度 | Preferred | 独立承担 / 主导 |

**Weak Example**：（缺失时无此信号）

**Strong Example**："独立承担 XX 部件从概念方案到量产 SOP 全流程，对接模具、工艺、电气三部门。"

**Verification Rule**：Scope 必须有边界词（从…到… / 对接…）；"全程参与"无边界不达标。

**Confidence**：Medium

## 4. 量化锚点速查（Q4 Impact 细化）

| 锚点类型 | 示例表述 | 验证要求 | 可得性档位 |
|---------|---------|---------|:--:|
| 减重 | "通过拓扑优化减重 X% / Ykg" | 有方法（拓扑优化）与对象 | 工程指标 |
| 成本 | "单台成本降低 X 元 / BOM 成本压缩 X%" | 有对比基线 | 业务结果 |
| 寿命 | "疲劳寿命从 X 次提升至 X 次" | 有验证（测试/仿真） | 工程指标 |
| 性能 | "一阶固有频率从 X Hz 提升至 Y Hz" | 有仿真或实测数据 | 工程指标 |
| 精度 | "重复定位精度 ±Xmm" | 有测试方法 | 工程指标 |
| 图纸量 | "独立完成 X 张+ 工程图 / X 套 BOM" | 有交付物 | 交付物 |
| 医械 | "完成 X 项设计验证测试，通过率 X%" | 有测试报告 | 工程指标 |

## 5. 动词强度（L1-L4 本语言族应用）

| 层级 | 本语言族动词 | 提级证据（必须显式出现在原始文本） |
|------|------------|--------------------------------|
| L1 参与 | 参与、协助、支持 | 无提级空间 |
| L2 执行 | 设计、绘制、选型、校核、出图 | 有交付物（图纸/模型/选型单/报告） |
| L3 主导 | 主导、独立完成、推动落地 | 责任证据：方案选择、评审通过、技术路线定夺 |
| L4 体系 | 搭建（设计规范/平台化/标准化） | 体系级证据：规范/流程/复用资产 |

规则：动词层级 ≤ 证据层级；提级必须标注证据锚点（引用原始文本片段）。

**结果 ≠ 领导责任**（Responsibility Signal Ladder 关键原则）：
- 客户验收通过 ≠ 主导（需责任证据：负责交付 / 协调验收 / 处理验收问题）
- 方案获客户接受 ≠ 主导方案（售前方案认可不构成交付责任）
- 参与测试/评审/试制 ≠ 升主导（参与 FAT 不代表领导责任）
- 提级时输出证据锚点，无法锚定则保留原层级

**「负责」警示（v1.3）**：「负责」×3 以上 = HR 跳过信号——只描述职责范围非个人贡献。职责范围 → 条目头/description（事实通道）；bullet 用成果式动词（独立完成/主导/优化/重构）+ 方法 + 量化结果。动词与职级匹配：执行层「协助/参与/完成」、骨干「主导/设计/优化」——层级错配反向扣分。

## 6. 项目分组惯例

- **命名**：`[产品名/系统名] — [阶段/任务]`，如"Project-A 生化分析仪 — 核心结构校核"
- **组织**：按产品线（生化/发光/酶标）或技术方向（传动/结构/热管理）；医械按注册分类；机器人按关节系统/本体/末端执行器
- **每项目 2-4 bullet**，按 STAR 拼接；医械法规关键词（ISO 13485、DHF、NMPA）至少出现在一个项目中
- **项目概述写 description**（Entry Contract v0.2）：第一行写清项目做什么、解决什么问题、规模亮点——S 背景不进 bullet

### 样机制作与测试经历专项（v1.3，初级工程师最稀缺、最有价值的经历）

「设计到制造鸿沟」的跨越经历最能区分新手和老手，按四段写：

```
装配问题（干涉/焊接变形/夹紧不足）→ 根因分析 → 解决方案 → 验证结果
```

- 问题必须具体（什么件、什么现象），"装配困难"泛称无价值
- 根因分析写方法（尺寸链计算/公差分析/实测比对）
- 验证结果落工程指标档（间隙控制 ±X / 一次装配合格率 X%）或确定性终点（通过量产验证）
