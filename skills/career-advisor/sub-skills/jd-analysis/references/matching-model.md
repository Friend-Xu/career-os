# 匹配度计算模型

JD 要求 ↔ 候选人证据的映射、评分与差距分类。

---

## 一、三入口模式

```
模式A: 完整模式 — 有简历（PDF/DOCX/文本）
  → 从简历提取技能清单（复用 skill-audit-guide.md 的提取规则）
  → 完整七大类技能映射

模式B: 快速模式 — 无简历，用户口述3-5项核心技能
  → 仅做核心技能匹配，标注"数据不完整"
  → 软技能/领域知识等维度使用默认值

模式C: 复用模式 — 已有 career-transition 技能画像
  → 直接读取 career-transition 输出的技能画像
  → 完整的七大类技能 + 熟练度 + gap备注
```

---

## 二、多维度加权评分

```
匹配度 = 硬技能(25%) + 经验(20%) + 领域知识(15%) + 差异化优势(15%)
       + 软技能/文化(15%) + 学历/证书(10%)
```

| 维度 | 权重 | 评分依据 | 数据来源 |
|------|:--:|------|---------|
| 硬技能 | 25% | JD要求的技术栈、工具 vs 候选人技能清单 | 简历/技能画像 |
| 经验 | 20% | 工作年限 + 项目类型 + 行业经验 vs JD要求 | 简历/技能画像 |
| 领域知识 | 15% | 行业知识、标准、法规 vs JD行业背景 | 简历/技能画像 |
| 差异化优势 | 15% | 候选人独有的、纯目标方向候选人不具备的优势 | 推断（仅转行背景激活） |
| 软技能/文化 | 15% | JD软技能信号 vs 候选人沟通/人际/管理能力 | 简历/技能画像 |
| 学历/证书 | 10% | 学历 + 专业证书 vs JD硬门槛 | 简历 |

### 硬门槛一票否决

学历/证书不满足JD硬门槛（明确标注"要求"而非"优先"）→ 标注"硬门槛不满足"，不计算综合分。

### 每维度评分（1-5分制）

| 分数 | 含义 |
|:--:|------|
| 5 | 超出要求（JD要求熟练，候选人精通） |
| 4 | 完全满足（等级匹配） |
| 3 | 基本满足（差半级） |
| 2 | 部分满足（差一级） |
| 1 | 不满足（差两级以上或零基础） |

## 三、证据锚定：二维映射表

### 核心原则

每个声称的技能匹配必须有可追溯的候选人证据。无证据 = 不计入匹配。

### 映射表

```
JD要求              | 要求等级 | 候选人证据                        | 候选人等级 | 匹配
Python数据分析       | 熟练     | 2年用pandas做用户行为分析           | 熟练       | ✓ 完全
SQL复杂查询          | 熟练     | 写过join/subquery但不会窗口函数     | 接触过     | △ 部分
Docker/K8s          | 接触过   | 无经验                            | 零基础     | ✗ 缺失
跨部门协作           | 熟练     | 跟产品+运营合作过3个项目            | 熟练       | ✓ 完全
```

### 匹配状态判定

```
候选人等级 ≥ JD要求等级 → ✓ 完全匹配
候选人等级 = JD要求等级-1级 → △ 部分匹配
  例外：JD要求=精通(4)，候选人=熟练(3) → △
        JD要求=熟练(3)，候选人=系统自学(2.5) → △（加速器适用）
候选人等级 ≤ JD要求等级-2级 → ✗ 缺失
```

### 红线约束

- "我没做过但我可以学" → 标注为"用户声称可学"，不计入匹配
- "学过但没有实践经验" → 标注为"系统自学"(2.5)，按加速器规则处理
- JD要求"精通"而候选人只是"用过几次" → 诚实降级

### 证据来源标注

`[简历·第X段经历]` / `[用户口述]` / `[推断·基于XX]` / `[career-transition·技能画像]`

## 四、差距可补救性分类

| 分类 | 定义 | 判定标准 | 策略 | 在优先级矩阵中的位置 |
|------|------|---------|------|------|
| **Quick Fill** | <2周可补 | 已有基础+只需调整方向 | 面试前搞定 | → Quick Win 或 Defer |
| **Medium Fill** | 2周-2月可补 | 有理论基础+缺实践 | 做一个Demo项目 | → Critical Path 或 Quick Win |
| **Hard Fill** | 2-6月可补 | 需要系统学习 | 在职学习 | → Critical Path |
| **Unfillable** | 不可短期弥补 | 硬性门槛无法绕开 | 诚实标注，给绕行策略 | → Ignore |

### 两套分类的关系

- **时间分类**（Quick/Medium/Hard/Unfillable）：判断"补一个技能要多久"
- **优先级分类**（Critical Path/Quick Win/Defer/Ignore）：判断"应该先补哪个"
- **映射规则**：技能的重要度决定优先级
  - Critical 技能 × Quick Fill → Quick Win（重要+容易=先做）
  - Critical 技能 × Medium/Hard Fill → Critical Path（重要+难=重点投入）
  - Important/Supporting 技能 × Quick/Medium/Hard Fill → Defer（入职后补）
  - 任何 Unfillable → Ignore（不投入时间补，用绕行策略）

## 五、转行者加成

**始终为转行背景用户激活**（不设匹配度门槛）。

转行背景判定：用户当前岗位/行业 ≠ 目标岗位/行业，且存在跨领域迁移。

> 差异化优势维度（15%）在非转行场景下为 0 分。转行场景下激活该维度。

### 可迁移技能映射

将当前方向技能翻译为目标方向对应技能：
- "SolidWorks机械设计 → 机器人本体结构设计（工具相同，设计思维相通）"
- "IATF 16949体系经验 → 理解受控流程和质量追溯（通用能力）"

### 跨领域优势

"作为转行者，你的[当前背景]让你比纯[目标方向]出身的人多出[独特优势]"

### 加速潜力

复用 career-transition 的加速器逻辑：
- gap方向 = 目标方向 → 学习时间缩短 30-50%
- 系统自学过的知识 → 评级为 2.5 而非 2.0

### 不改变什么

- 不改变硬门槛一票否决
- 不改变四象限位置
- 不改变 JD 质量评估结果

## 六、边界敏感性标注

| 边界 | 敏感区间 | 标注内容 |
|------|:--:|------|
| 直接投 vs 定制后投 | 55-75% | "匹配度靠近决策阈值，某技能评级下调可能改变建议" |
| 定制后投 vs 观望 | 45-55% | "匹配度靠近边界，建议投一份试市场反馈" |

快速模式不计算精确百分比，输出定性判断。
