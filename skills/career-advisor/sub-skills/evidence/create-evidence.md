# 证据创建（入口 A：主动沉淀）

> career-advisor 子模块（evidence）。由主 SKILL.md / AI 面板路由加载，不作为独立 skill 运行。
> 对应 M2 文档 `EVIDENCE-MODEL-M2-v0.1.md` §5 入口 A。输出契约：`evidence-output-schema.md`。

**用户说"我想整理一个项目经历" → 对话式引导 → 生成证据条目。**

不做填表，不做审核负担（H1/H2 教训）——一次对话问 3-5 个问题，能答多少答多少，半成品合法。

---

## 工作流

```
1. 确认事件
   "这次经历大概是什么？（一个项目/一段工作/一次交付）"

2. 引导六问（顺序引导，不问不追问）
   事件 → 角色 → 贡献 → 方法 → 验证 → 结果

   分步问（每次一个问题，不要一次抛出整表）：
   - 你在里面是什么角色？
   - 你实际负责/做了什么？（这是贡献，不是岗位职责）
   - 用了什么方法或工具？
   - 怎么验证有效？（测试/评审/用户反馈…）
   - 结果或影响是什么？（指标变化、被采纳…）

3. 结构化落盘
   按 evidence-output-schema.md 生成
   写 evidence/{日期}-{事件名}.md
   status: candidate（未确认）
   source_type: user_input

4. 确认（可选，用户愿意时）
   "整理成这样，对吗？" → 确认 → 改写 status: trusted + verification
```

---

## 规则

1. **禁止编造**：用户没说"结果"就不填 impact；没说验证方式就不填 validation——半写状态合法，不强行补全
2. **一次一个问题**：分步引导，禁止一次抛出六个问题的表单
3. **role 是身份不是岗位责任**："机械结构负责人"是 role，"负责机架和传动模块设计"是 contribution
4. **内容自足**：口述内容完整写入文件，不依赖"简历第几页"这类会失效的引用
5. **重复整理同一事件**：照常写新暂存名文件，引擎自动分配新 ID（历史保留）
6. 文件写 `evidence/` 目录（不是 decisions/、不是 jobs/）
