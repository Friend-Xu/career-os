# IKIGAI 四问指南

对话式自我认知的追问技巧和归纳方法。不做心理测量问卷，用四个开放问题帮用户厘清自己的偏好和盲区。

---

## 为什么用 IKIGAI 而不是 RIASEC/MBTI 测评

1. **Claude Code 不适合做长问卷**：30+ 题的交互式测评体验差，用户中途流失
2. **IKIGAI 是对话不是测试**：四个开放问题，用户怎么说都行，自由度高
3. **IKIGAI 自带"盲区检测"**：四个圈中哪个弱暴露职业风险（热爱但赚不到钱/擅长但没市场）
4. **RIASEC 作为补充标签**：问完后映射到 1-2 个 RIASEC 类型，给用户一个"原来我是 X 型"的认知锚

## Cross Off 排除法（IKIGAI 前置步骤）

### 为什么先做排除

对于回答不了"你喜欢什么"的学生，"你确定不想要什么"更容易回答。
排除法有三个作用：
1. **热身**：从否定开始比从肯定开始更容易
2. **建立边界感**：知道自己不要什么，能帮助定义自己要什么
3. **过滤降噪**：18 个方向中有些方向因为工作特征（出差/倒班/重复性）就可以直接排除

### 排除清单

```
以下工作特征中，有没有你确定不想要的？（可以多选）

□ 整天对着电脑，不怎么跟人交流
□ 经常出差，一个月大半时间在外面
□ 倒班/on-call，设备半夜坏了要去修
□ 重复性高，每天做的事情差不多
□ 高压快节奏，deadline 追着跑
□ 跟数字和报表打交道为主，不需要动手
□ 都没有特别排斥的
```

### 排除映射表

| 排除项 | 受影响的方向 | 处理方式 |
|--------|------------|---------|
| 整天对着电脑 | CAE仿真、结构设计、工业软件开发、嵌入式 | 画像卡加注"⚠ 以电脑工作为主" |
| 经常出差 | 技术支持/应用工程师、非标自动化 | 技术支持直接降级；非标标注 |
| 倒班/on-call | 设备工程师 | 直接降级到可做备选 |
| 重复性高 | 质量工程师、设备工程师、模具设计（量产阶段） | 画像卡加注 |
| 高压快节奏 | 非标自动化、技术销售 | 画像卡加注 |
| 跟数字报表打交道 | 质量工程师、采购/供应链 | 画像卡加注 |

### 排除后的处理

- 被排除 ≥3 项 → 用户可能有较清晰的边界感，IKIGAI 追问时参考排除项反向推导偏好
- 被排除 1-2 项 → 过滤对应方向后继续 IKIGAI
- 全选"都没有" → 直接进入 IKIGAI（用户可能确实没有明确好恶，或还在探索期）
- 入口 A 用户（深度对比）→ Cross Off 可选，跳过不影响流程

## 四问流程

### 第一问：热爱 (What you love)

**目的**：找到用户的内在动机——什么让他/她愿意投入时间。

**问法**：
```
"你对现在的专业或工作中，哪些部分做起来最有热情？
不用想'应该喜欢什么'，就说实际感受。

比如：动手拆装东西、数学建模仿真、写代码调试、跟人沟通协作、
画图做设计、钻研一个问题、把事情理顺...

（也可以说'都不喜欢'，这本身就是一条重要信息）"
```

**追问技巧**：
- 用户说得抽象（"我喜欢技术"）→ 追问"具体是哪个环节？做设计/做实验/调代码/看论文？"
- 用户说"不知道" → 缩小范围"那回顾一下大学课程，哪门课你学得最轻松？"
- 用户说"都不喜欢" → 不否定，问"那你平时业余时间花最多时间做什么？"

**归纳方式**：
```
从你的回答看，你的兴趣倾向是：
  - [兴趣标签1]（来自你说的XXX）
  - [兴趣标签2]（来自你说的YYY）
→ 对应 RIASEC 中的 [类型]
```

**产出**：2-3 个兴趣标签 + 1 个 RIASEC 类型

---

### 第二问：擅长 (What you are good at)

**目的**：找到用户的能力优势——这不一定等于他热爱的。

**问法**：
```
"你觉得自己哪方面能力比较突出？不一定是专业上的，任何方面都算。

比如：空间想象力强（看图做三维推理）、逻辑推理好（解题快）、
手巧（实验动手能力）、沟通说服（让人接受你的观点）、
细致认真（不出错）、创意多（总能想出新点子）...

也可以想想：同学/同事经常夸你什么？"
```

**追问技巧**：
- 用户说"没什么特别擅长的" → 问"那不擅长什么？"反推
- 用户把兴趣当擅长 → 区分"你喜欢 X，但做 X 的水平在同龄人中大概排多少？"
- 提供具体场景"比如做课程设计时，你是画图强还是算力学的强？"

**归纳方式**：
```
你的能力优势是：
  - [能力标签1] — 在XXX场景中体现
  - [能力标签2] — 在YYY场景中体现
→ 这类能力在 [方向A/方向B] 中能发挥最大价值
```

**产出**：2-3 个能力标签

---

### 第三问：被需要 (What the world needs)

**目的**：将用户注意力拉向市场——个人偏好和市场需求的交叉点是职业安全区。

**问法**：
```
"你观察到哪些行业或岗位在招人？
身边的同学、学长学姐都去哪工作了？
你听过哪些公司名字在你这个领域招人比较多？

（这一步我会结合搜索数据帮你验证，所以凭你的印象说就行）"
```

**追问技巧**：
- 用户说"不太清楚" → 问"你们专业上一届最多人去的公司/行业是什么？"
- 用户只说出一个方向 → 问"除了这个，还有没有你听过的别的方向？哪怕你不感兴趣"

**处理方式**：
- 用户说出的方向在 Step 4 用搜索数据交叉验证
- 如果用户说的和搜索数据显示的趋势不一致 → 标注"你的观察和公开数据有偏差，可能是 X 原因"
- 这一步的产出直接影响 Step 4 的搜索优先级

**产出**：2-3 个市场方向标签 + 与搜索数据交叉验证

---

### 第四问：有报酬 (What you can be paid for)

**目的**：明确用户对钱的态度——这是 IKIGAI 中最容易被回避但最关键的一问。

**问法**：
```
"你对薪资的期待是什么？

A. 起薪高最重要 — 毕业就要能独立，不太能接受低薪
B. 天花板高最重要 — 起薪低没关系，但上限要高，10年后能拉开差距
C. 平衡 — 别太低就行，更看重其他方面
D. 够用就行 — 薪资不是主要考虑

（这个没有对错，只是帮你匹配适合的方向）"
```

**追问**：
- "你对'够用'的定义是什么？比如期望第一年拿到多少？第5年呢？"
- "如果有个方向起薪低但 5 年后翻倍，另一个起薪高但涨得慢，你倾向哪个？"

**归纳方式**：
```
薪资偏好: [起薪优先/成长优先/平衡/够用就行]
这意味着：
  - 起薪优先 → 优先推荐入门岗薪资高的方向（如非标设计、技术支持）
  - 成长优先 → 优先推荐天花板高的方向（如CAE仿真、机器人研发）
  - 平衡     → 综合评估，不做极端推荐
```

**产出**：薪资偏好类型

## IKIGAI 四问产出

四问完成后，ikigai-guide 本身的职责到此结束。后续的**标签归纳**和**交叉验证**由 `SKILL.md` Step 3b 执行。

> **已废弃**：v1.0 中的"IKIGAI 交集图输出"（四圈维恩图 + 交集分析 + 盲区检测表）。
> 自 v1.1 起，交集图被"交叉验证"替代（SKILL.md Step 3b）。
> 盲区检测保留在 SKILL.md Step 3b 末尾，逻辑不变。
> 此处不再维护重复的交集分析格式。

---

## 质量规则

1. 不做诊断、不贴标签——"你可能偏 X 型"不是"你就是 X 型"
2. 尊重用户的"不知道"——不知道是正常的，追问帮用户发现而非强行归纳
3. IKIGAI 是讨论起点不是终点——最终推荐以搜索数据（Step 4）为主
4. 如果用户四个圈都弱（年轻学生常见），不强行填空，标注"尚在探索期，优先选择市场信号强的方向入行"
