# 转行可行性分析框架

参考来源：
- Manning & Aguirre (2026), "Adaptive Capacity and Career Transitions", NBER Working Paper No. 34705 — 752 个职业的 O*NET 技能相似度度量 + 地理密度 + 财务缓冲的复合评分
- Nedelkoska et al. (2018), "Skill Transferability and Migration" — O*NET 120+ KSA 条目的 Jaccard 相似度实证验证，工作者在相似职业间迁移概率高达 4.98 倍
- Burning Glass Institute, "Skills-First Working Initiative" — 基于 1650 万就业档案的技能邻接度概念
- O*NET Center, "Related Occupations Technical Report" — 6 维度欧氏距离的 Starter/Change 算法

> 本文件将这些框架简化为定性版用于职业方向间的迁移评估。

---

## 触发条件

仅在 Step 1 问题三用户选了 **C（想转行但不知道怎么转）** 或用户主动说"我想从 X 转到 Y"时触发。

如果用户只是做初次方向选择（没有"当前职业"），跳过此模块。

---

## 四维分析

### 1. 技能重叠度（高/中/低）

```
重叠度 = 当前职业已掌握的技能 ∩ 目标方向所需核心技能 / 目标方向所需核心技能总数
```

| 重叠度 | 判定 | 含义 |
|:--:|:--:|------|
| ≥ 60% | **高** | 可以直接投简历，不需要额外学习 |
| 30-60% | **中** | 需要 3-6 个月自学/培训 |
| < 30% | **低** | 需要系统学习（6个月-2年），或需要回学校 |

**输出格式**：
```
重叠技能：[技能A, 技能B, 技能C] — 这些可以直接迁移
需要新学：[技能X, 技能Y, 技能Z] — 这些需要在转行前掌握
```

### 2. 转行成本（时间 + 金钱）

| 成本等级 | 时间 | 需要做什么 | 适合人群 |
|:--:|:--:|------|------|
| **低** | 1-3 个月 | 自学 + 做 1-2 个项目 + 修改简历 | 技能重叠度高的转行 |
| **中** | 3-12 个月 | 系统上课/培训班 + 实习/兼职项目 | 技能重叠度中的转行 |
| **高** | 1-3 年 | 考研究生/第二学位/从头积累经验 | 技能重叠度低的转行 |
| **极高** | 3年+ | 完全换赛道，需要新学历+新人脉 | 跨界转行 |

### 3. 中间跳板

有些转行不能一步到位，需要中间岗位过渡：

**示例**：
```
机械工程师 → 嵌入式工程师
  中间跳板: 机电一体工程师（机械+简单电控混合岗）
  过渡时间: 在中间岗位做 1-2 年，边做边学

机械设计 → 工业软件开发
  中间跳板: CAD二次开发工程师（用C++/C#写SolidWorks插件）
  过渡时间: 自学编程 6 个月 + 在工作中学

销售 → 产品经理
  中间跳板: 售前/解决方案工程师（懂客户+懂产品）
  过渡时间: 直接转，销售经验是产品经理的核心竞争力
```

**如果找不到中间跳板**，如实告知"该转行路径缺少自然过渡岗位，需要'硬转'"。

### 4. 地理密度（目标方向在用户当前/目标城市的岗位密度）

| 密度 | 判定 |
|:--:|------|
| **高** | 该方向在全国主要城市都有岗位，不挑城市 |
| **中** | 该方向集中在特定城市群（如半导体在上海/北京/深圳） |
| **低** | 该方向岗位高度集中在一两个城市，需要搬家 |

**输出**：告知用户目标方向在哪里岗位多，如果刚好匹配 city-advisor 的结果，标注"你之前选的城市 [X] 对这个方向是加分项"。

## 转行可行性总评

综合四维分析，给出转行可行性评级：

| 评级 | 含义 |
|:--:|------|
| **可行** | 技能重叠度高 + 成本低 + 有中间跳板 → 建议 3 个月内开始行动 |
| **可行但有代价** | 技能重叠度中 + 需要投入时间/金钱 → 建议做 6 个月学习计划 |
| **困难但可能** | 技能重叠度低 + 需要回学校或从头开始 → 建议先兼职尝试（副业/开源项目）测试自己是否真的喜欢 |
| **不建议** | 技能、市场、地理三重不利 → 如果只是为了"逃离"当前方向，建议先找当前方向内更好的机会 |

## 输出模板

```
## 转行路径分析: [当前方向] → [目标方向]

### 技能重叠度: [高/中/低]
- 可直接迁移: [技能列表]
- 需要新学: [技能列表]

### 转行成本: [低/中/高/极高]
- 时间估算: [X 个月/年]
- 建议路径: [自学/培训/回学校/考证]

### 中间跳板
- 推荐过渡岗位: [岗位名]
- 过渡时间: [X 个月/年]
- 跳板策略: [在过渡岗位做什么来积累目标方向的经验]

### 地理因素
- 目标方向岗位集中在: [城市列表]
- 与你当前/目标城市的匹配度: [高/中/低]

### 总评: [可行/可行但有代价/困难但可能/不建议]
[一句话总结 + 具体第一步行动建议]
```

---

## 质量规则

1. **不美化转行难度**：如果确实很难（如"文科转AI算法"），诚实告知，不画大饼
2. **给具体第一步**：不说"你可以学习编程"，说"从 B 站 XX 课程 + 做一个 SolidWorks 插件开始"
3. **中间跳板是核心价值**：很多转行咨询只告诉"可以转"，不告诉"怎么转"。中间跳板是本模块最有价值的部分
4. **数据标注**：薪资和岗位信息标注来源和年份，转行成功案例标注"个例，不代表普遍情况"
