# 职业路径规划
>
> 本文件是 career-advisor skill 的子模块。由主 SKILL.md 路由加载，不作为独立 skill 运行。

**输入你的专业或背景，输出所有可能的职业方向及其适配度排序。**

不预设方向偏好，不做心理测量问卷——从路径枚举 + IKIGAI自我认知 + 市场信号三个角度，
帮你发现适合自己但可能没想到的方向，以及转行的可行路径。

## 工作流总览

```
Step 1: 三问定框架 → 专业/背景 + 阶段 + 困惑点
Step 2: 方向画像卡 → Read 索引 → 匹配专业 → Read ../../references/directions/[专业].md
Step 3: IKIGAI 四问 + 交叉验证 → Read references/ikigai-guide.md
Step 4: 路径画像   → 并行搜索每个方向的薪资/天花板/门槛/趋势
Step 5: 加权打分   → Read references/path-scoring-model.md
Step 6: 输出报告   → Read references/path-template.md
```

## Step 1: 三问定框架

不要一次性抛出三个问题。依次问，根据上一个回答决定下一个问题的呈现方式。

### 问题一：专业/背景

```
你的专业或当前职业是什么？（自由输入）
例如："机械工程"、"计算机科学"、"没上过大学，做过3年销售"
```

- "还没定方向" → 问有没有感兴趣的行业，没有则用通用搜索簇

### 问题二：阶段

```
你现在是什么阶段？
A. 在校/应届 — "还没入行，想知道有哪些方向"
B. 初入职场(0-3年) — "入了行但不确定对不对，想看看其他可能"
C. 转行窗口(3-6年) — "想转行，需要知道怎么转"
D. 纯了解 — "只是想了解一下自己的选择空间"
```

- 选 C → Step 5 转行分析模块激活
- 选 A/B → 跳过转行分析，聚焦初次方向选择

### 问题三：三个入口（根据自知程度路由）

```
你现在对自己的方向，知道多少？

A. 心里大概有方向了，想深入对比  → "深度对比"路径
   你已经有 2-3 个候选方向，需要的是薪资/前景/入行路径的详细对比来帮你做决定

B. 知道想去什么行业，不知道什么岗位适合 → "行业筛选"路径
   比如"我想去新能源行业，但不知道能做什么岗位"

C. 完全不知道，想全面了解 → "全景探索"路径
   没有明确偏好，需要先看到所有选项再慢慢缩小
```

**路由逻辑**（影响后续步骤行为）：

| 入口 | Step 2 | Step 3 | Step 4 |
|------|--------|--------|--------|
| A 深度对比 | 只展示用户提到的方向画像卡 | 聚焦：IKIGAI 四问针对这几个方向展开 | 深度搜索 2-3 个方向（更多搜索词变体 + 更多数据源） |
| B 行业筛选 | 先问行业 → 只展示该行业相关的画像卡 | 标准 IKIGAI + Cross Off | 搜索该行业内用户感兴趣的 3-5 个 |
| C 全景探索 | 全量画像卡扫描 | Cross Off 排除法 + IKIGAI 四问 | 搜索用户感兴趣的 3-5 个（当前默认） |

## Step 2: 方向画像卡

Read `references/career-path-map.md`（索引文件，含路由表和行业标签），根据用户专业匹配对应 directions/ 文件（位于 `../../references/directions/`），Read 该文件获取完整方向表+画像卡。

### 核心原则

**不给成绩单。** 应届生看到"CAE仿真工程师"这个名字，不知道每天干什么、不知道适不适合自己。
Step 2 的目标是让你**看懂每个方向**，然后自己筛选。

### 执行方式

1. 根据用户专业查索引文件（career-path-map.md）的路由表，Read 对应的 `../../references/directions/[专业].md`，获取三个层级的方向列表

2. **根据 Step 1 入口路由**：
   - **入口 A（深度对比）**：跳过全量画像卡，直接展示用户已提到的方向画像卡。确认语："你提到了 [方向X] 和 [方向Y]，先深入看这两个。如果看完觉得不够，随时可以回来看更多。"
   - **入口 B（行业筛选）**：先问行业偏好。career-path-map.md 底部有 18 个行业标签可参考。
    展示语："你想去哪个行业？比如：新能源汽车、医疗器械、电子半导体、互联网..."
    只展示该行业对应的方向画像卡（匹配画像卡的"主要行业"字段）。
   - **入口 C（全景探索）**：全量分组展开画像卡

3. 用户看完画像卡后自然筛选，选 3-5 个感兴趣的方向

### 画像卡展示话术

```
"你的专业有 X 个可选方向，分成三组。先扫一遍，看看哪些觉得'这可能是我'。

▸ 直接对口方向 — 你学的东西直接用得上

  [方向名1]
  画像：[2-3句话描述日常做什么]
  适合：[什么样的人会喜欢这个方向]
  IKIGAI标签：兴趣→[标签] | 能力→[标签]

  [方向名2]
  ...

▸ 可迁移方向 — 不完全对口但技能能用上
  ...

▸ 跨界方向 — 需要学新东西但走得通
  ...

→ 哪些方向让你觉得'想了解更多'？选 3-5 个，接下来深入看。"
```

### 方向数量引导

如果用户想全部评估（>5个方向）：
"画像卡看完后，建议先聚焦 3-5 个最感兴趣的方向深入对比。
其余方向保留画像卡信息，可以随时回来看。选 3-5 个就好。"

不强限制，但引导收敛。

### 现实锚点：学校就业报告

如果用户提供了学校信息，在画像卡展示前或展示后，搜索该校的就业去向数据，
作为画像卡的"现实锚点"——不是"这个方向理论上是什么"，而是"跟你同校同专业的人实际上去了哪"。

**搜索策略**（按优先级）：
1. `"[学校名] 毕业生就业质量年度报告 [最近年份]"`
   → 找分专业的行业流向、典型雇主、平均薪资
2. `"[学校名] [专业名] 就业 去向 2024 2025"`
   → 如果报告不公开分专业数据
3. `"[学校名] 就业信息网 毕业生去向"`
   → 有些学校不发布PDF报告但在就业网上有数据
4. 降级：使用麦可思研究院的**学科门类**数据（如"机械类本科 平均起薪 行业分布"）

**可获取的数据字段**（按可靠性排序）：
- 行业流向（如"制造业 42%，汽车 18%..."）→ 最可靠，几乎所有报告都包含
- 典型雇主（如"主要去向：联影、三一、比亚迪..."）→ 大部分报告包含
- 平均起薪 → 约 60% 的报告包含
- 分专业细分 → 211/985 学校较全，普通学校可能不公开

**展示方式**（放在画像卡分组之前或之后）：
```
▸ 你们学校机械工程 2024 届实际去向：
  制造业 42% | 汽车 18% | 医疗器械 12% | 升学 15%
  典型雇主：联影医疗、三一重工、宁德时代
  平均起薪：10.5万/年 [学校就业报告·2024]
```

**如果搜不到**：诚实告知，标注"该校就业报告未公开分专业数据，以下方向画像基于全国平均情况"。

### 如果专业不在表中

使用通用搜索簇 + WebSearch 补充，标注"该专业不在预设映射表中，方向枚举基于搜索推理"。

### 画像卡覆盖说明

所有 8 个专业均有完整方向画像卡（日常+适合+IKIGAI标签+主要行业），按专业拆分到 `../../references/directions/` 目录下。
索引文件 `career-path-map.md` 提供路由表，按需读取对应专业文件（每次 ~70-230 行）。

**分层策略**：

| 层级 | 覆盖范围 | 展示方式 |
|------|---------|---------|
| Tier 1 | 8 个预设专业 | 完整画像卡 + 表格 + 全流程（来自 `../../references/directions/`） |
| 通用 | 不在以上 8 个专业中 | 索引文件中"通用搜索簇" + WebSearch 实时生成 |

> 每个专业文件 70-230 行，包含该专业所有方向的画像卡（日常+适合+IKIGAI标签+主要行业）。
> 画像卡基于 2026 年真实从业者分享和招聘市场数据编写。

## Step 3: Cross Off 排除 + IKIGAI 四问 + 交叉验证

Read `references/ikigai-guide.md` 获取追问技巧。

### Step 3a: Cross Off 排除法（30 秒预热）

在 IKIGAI 之前，先做一个轻量级排除。_（入口 A 用户可跳过，直接进入 IKIGAI）_

```
"在开始想'要什么'之前，先做 30 秒的排除练习。
以下工作特征中，有没有你确定不想要的？（可以多选）

□ 整天对着电脑，不怎么跟人交流
□ 经常出差，一个月大半时间在外面
□ 倒班/on-call，设备坏了半夜要去修
□ 重复性高，每天做的事情差不多
□ 高压快节奏，deadline 追着跑
□ 跟数字和报表打交道为主，不需要动手
□ 都没有特别排斥的"
```

**排除映射表**：详见 `references/ikigai-guide.md` 的 Cross Off 章节（权威源）。

> 如果用户全选"都没有"，直接进入 IKIGAI。如果排除 ≥3 项，可能反映用户对工作有较清晰的边界感，IKIGAI 追问时可以更聚焦。

### Step 3b: IKIGAI 四问

### 核心原则

- IKIGAI 四问放在画像卡**之后**——用户已有了基本认知，不再凭空想象
- 四问收集兴趣/能力/市场/薪资标签，与 Step 2 自选方向做**交叉验证**
- **不做评分**，做对比：自选 vs IKIGAI 指向，找重叠和差异

### 四问流程

依次问四个开放问题（详见 ikigai-guide.md）：

**第一问：热爱** — "你专业/工作中哪些部分做起来最有热情？"
**第二问：擅长** — "你觉得自己哪方面能力比较突出？"
**第三问��被需要** — "你观察到哪些行业/岗位在招人？"
**第四问：有报酬** — "你对薪资的期待？A.起薪高 B.天花板高 C.平衡 D.够用就行（可多选，如 A+B）"

### 交叉验证（替代原来的交集图）

四问完成后，不做评分，而是做对比：

```
"你的自选方向: [Step 2 选的方向]
 你的IKIGAI标签指向: [根据标签匹配的方向]

 ▸ 重叠: [方向列表] ← 直觉和偏好一致，重点深入
 ▸ 你选了但IKIGAI没指向: [方向列表] ← 为什么选它？是因为听别人说过还是真的感兴趣？
 ▸ IKIGAI指向但你漏了: [方向列表] ← 你可能没想过，但标签匹配，值得看一眼"
```

### Cross Off 与 IKIGAI 冲突处理

**Cross Off 优先于 IKIGAI 匹配。** 当 IKIGAI 标签指向某个方向，但该方向的核心工作特征被用户明确排除时，不应推荐。

```
处理逻辑：
1. IKIGAI 指向方向 → 检查该方向的画像卡"适合"字段是否包含被排除的特征
2. 如果包含 → 标注冲突，不放入"IKIGAI指向但你漏了"
   示例：用户排除"经常出差"，IKIGAI指向非标自动化
        → 非标画像卡明确写了"经常出差去客户现场装调试"
        → 标注"非标自动化跟你的标签匹配，但你排除了'经常出差'——
          这个工作出差频率确实高(可能50%+)。如果这个边界可以松动，值得重新考虑。"
3. 如果用户表示"这个边界可以松动" → 重新纳入评估
4. 如果用户坚持排除 → 尊重排除，不推荐

### IKIGAI 盲区检测

| 缺失的圈 | 风险 | 对方向选择的影响 |
|---------|------|---------|
| 热爱缺失 | "工作只是工作"，倦怠风险高 | 优先选天花板高的方向 |
| 擅长缺失 | 入行学习曲线陡，起步慢 | 优先选入门门槛低的方向 |
| 被需要缺失 | 方向小众，找工困难 | Step 4 重点验证市场信号 |
| 有报酬缺失 | 方向薪资低 | 明确告知，不做虚假承诺 |

## Step 4: 路径画像

> 以下搜索预计耗时 2-4 分钟，5-10 个方向并行搜索。

对用户选中的方向（通常 3-5 个），每个方向 6 个维度并行搜索：

| 维度 | 搜索内容 | 来源 |
|------|---------|------|
| 薪资曲线 | 起薪、3年/5年薪资、天花板 | WebSearch + Exa |
| 入行门槛 | 学历要求、技能要求、证书 | WebSearch |
| 天花板 | 头部岗位薪资、晋升路径 | WebSearch |
| 市场趋势 | 招聘量变化、行业前景、AI可替代性 | WebSearch + Exa |
| 地域分布 | 岗位集中在哪些城市 | WebSearch |
| 工作内容 | 日常做什么、加班、工作节奏 | WebSearch |

### 搜索模板

```
"[方向名] 薪资 2025 2026 起薪 天花板"
"[方向名] 招聘要求 学历 技能 2025"
"[方向名] 行业发展 前景 AI影响 2025 2026"
"[方向名] 岗位 城市分布 2025"
"[方向名] 日常工作 加班 真实体验"
```

如果用户提供了学校信息，额外搜索：
```
"[学校名] 校友 [方向名]"  ← 找校友在该方向的实际案例，验证可行性
```

用 Agent 并行派发，每个方向 2-3 个搜索变体。

## Step 5: 加权打分

Read `references/path-scoring-model.md` 获取完整评分细则。

### 打分流程

1. 对每个方向在 6 个维度上打出 1-10 分（或 1-5 分）
2. 总分 = (市场信号 3 维 × 50%) + (个人适配 3 维 × 50%)
3. 困惑点 A（不知道有哪些方向）→ 市场信号权重 +10%
4. 应用硬性门槛：入行可行性 < 3 自动降到可做备选
5. 分层展示

### 权重速查

| 维度 | 权重 |
|------|:--:|
| 入行可行性 | 20% |
| 薪资成长性 | 15% |
| 市场趋势 | 15% |
| IKIGAI 兴趣匹配 | 20% |
| IKIGAI 能力匹配 | 20% |
| 薪资偏好匹配 | 10% |

### 分层展示

| 总分 | 层级 | 展示方式 |
|------|------|---------|
| ≥ 7.0 | 高度匹配 | 默认展开，置顶，详细剖析 |
| 5.0-6.9 | 值得探索 | 默认展开，表格对比 |
| < 5.0 | 可做备选 | `<details>` 折叠 |

## Step 5b: 转行分析（可选）

Read `references/transition-model.md` 获取完整框架。

仅在 Step 1 选了 C（转行窗口）或用户主动说"我想从 X 转到 Y"时触发。

### 四维分析

1. **技能重叠度**（高/中/低）：列出重叠技能 + 需要新学的技能
2. **转行成本**（低/中/高/极高）：时间 + 金钱估算
3. **中间跳板**：有没有过渡岗位可以降低风险
4. **地理密度**：目标方向在用户城市的岗位密度

输出转行可行性评级：可行 / 可行但有代价 / 困难但可能 / 不建议。

## Step 6: 输出报告

Read `references/path-template.md` 获取完整模板。

### 输出结构

1. **IKIGAI 自画像**（200字以内）— Cross Off 排除项 + IKIGAI 标签
2. **三个方向深度展开** — 稳妥之选 + 高回报之选 + 你没想过的（各一页详细剖析）
3. **其余方向**（折叠）— `<details>` 内表格，标注类型和一句话
4. **转行路径图**（如有）— 技能桥 + 中间跳板 + 第一步行动建议
5. **尾部引导** — "确定方向后，用 city-advisor 看哪个城市适合这个方向"

## 边界情况

### 专业不在映射表中
从专业名提取关键词 + 通用搜索簇。标注"该专业不在预设映射表中，方向枚举为搜索推理结果"。

### 用户说"不知道喜欢什么/擅长什么"
IKIGAI 四问中不强行归纳。缩小范围追问（"哪门课最轻松？""别人常夸你什么？"），如果仍然答不上来，标注"尚在探索期"，市场信号权重从 50% 提升到 60%（入行可行性 25%、市场趋势 20%），从兴趣和能力各减 5%。与 path-scoring-model.md 的困惑点权重调整规则保持一致。

### 转行方向跨度极大（如文科转AI）
诚实告知难度（"技能重叠度低，需要回学校或从头自学 1-2 年"），不强推。建议先在业余时间测试（"周末做一个 X 项目，看自己是否真的喜欢"）。

### 候选方向过少（<3个）
如果用户专业冷门只映射到 1-2 个方向，主动扩展到可迁移和跨界方向。标注"你的专业直接对口方向较少，已扩展到可迁移方向"。

### 筛选后候选方向为 0
入口 B（行业筛选）可能将全部方向过滤掉（如用户选了"金融"但机械专业没有任何方向标注该行业），或 Cross Off 排除了所有方向。此时主动展示**不匹配的原因**，并建议放宽筛选条件："你的筛选条件（[行业] + [排除项]）过滤掉了所有方向。要不要放宽某个条件？比如看看机械专业能去[行业]的跨界方向？"

### 完全搜不到信号
诚实告知，标注数据源局限。方向信号稀疏本身就是一条信息（可能太小众或正在衰退）。

---

## 质量规则

1. 每条信号标注来源类型和年份
2. 薪资数据标注年份和来源平台
3. 推断类判断标注 `[推断]`，与事实类信息区分
4. 查不到就说查不到，不编造数据
5. IKIGAI 结果是讨论起点不是诊断——"你可能偏 X 型"不是"你就是 X 型"
6. 转行分析不给虚假希望——难就是难，给具体的"怎么开始"而不是空洞的"可以实现"
7. 市场信号硬门槛不可绕过——入行可行性 < 3 的方向，不管多喜欢都诚实降级
